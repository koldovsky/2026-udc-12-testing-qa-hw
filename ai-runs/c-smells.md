# Тестові запахи в `app/test/unit/`

Переглянуто всі чотири файли unit-тестів і відповідний код у `app/src/`. Нижче наведено конкретні проблеми якості перевірок; це не твердження про наявність помилок у застосунку. Рядки вказують на проблемну перевірку або початок відповідного фрагмента. Приклади пропущених регресій отримано аналізом коду, без його зміни.

## 1. Перевірка власної заглушки замість застосунку

- **Файл:рядок:** `app/test/unit/tariff.test.js:80–83`
- **Тест:** `a 45-minute classic ride costs 50 UAH`
- **Запах:** Mocking the SUT / tautological test — підміна об’єкта тестування.
- **Чому це проблема:** `priceRide` — локальний `mock.fn`, який завжди повертає заздалегідь задані 5000. Справжній `quote` взагалі не викликається. Перевірки суми й кількості викликів підтверджують лише поведінку щойно створеної заглушки; будь-яка помилка тарифікації залишить цей тест зеленим.

## 2. Очікування повторює реалізацію та використовує її константи

- **Файл:рядок:** `app/test/unit/tariff.test.js:32`
- **Тест:** `e-bikes are billed at the e-bike rate`
- **Запах:** Duplicated production logic / non-independent oracle.
- **Чому це проблема:** Очікуване значення обчислюється тією ж формулою округлення блоків, що й у `chargeFor`, з імпортованих `BLOCK_MINUTES`, `RATES.ebike` та вже обчисленого `result.minutes`. Помилкова зміна тарифної константи змінить і фактичний, і очікуваний результат. Для заданих 75 хвилин незалежним очікуванням було б 12000 копійок; поточний тест перевіряє внутрішню узгодженість, а не правильність тарифу.

## 3. Перевіряється лише форма деталізованої ціни

- **Файл:рядок:** `app/test/unit/tariff.test.js:15–20`
- **Тест:** `quote returns an itemised price`
- **Запах:** Weak assertions / superficial oracle.
- **Чому це проблема:** Для трьох різних поїздок перевіряються тільки невід’ємність суми, тип `minutes` і наявність масивів. Реалізація, яка для всіх цих входів повертає `{ total: 0, minutes: 0, discounts: [], fees: [] }`, пройде тест. Відмінності між безкоштовною, звичайною та електричною поїздками фактично не перевіряються.

## 4. Величина абонементної знижки не перевіряється

- **Файл:рядок:** `app/test/unit/tariff.test.js:45–46`
- **Тест:** `subscription on a long e-bike ride`
- **Запах:** Weak assertions / incomplete oracle.
- **Чому це проблема:** Достатньо запису з кодом `subscription` і будь-якого зменшення ціни. Знижка в одну копійку замість 20 % пройде тест. Для 100 хвилин базове нарахування становить 16000, знижка — 3200, підсумок — 12800 копійок; жодне з цих значень не зафіксоване.

## 5. Назва обіцяє перевірку 30 %, але перевіряється будь-яка знижка

- **Файл:рядок:** `app/test/unit/tariff.test.js:58–61`
- **Тест:** `night rides get 30 % off`
- **Запах:** Misleading test name / weak assertion.
- **Чому це проблема:** Перевірки підтверджують базову ціну, кількість і код знижки, але тільки нерівність для підсумку. Нічна знижка 1 % або 90 % також пройде. Для нарахування 2500 очікуються знижка 750 і підсумок 1750 копійок.

## 6. Кількість зборів використовується замість перевірки їхнього змісту

- **Файл:рядок:** `app/test/unit/tariff.test.js:66`
- **Тест:** `a bike kept over a day and left outside the zone pays both fees`
- **Запах:** Count-only assertion / incomplete oracle.
- **Чому це проблема:** `fees.length === 2` не доводить наявність саме `out-of-zone` та `unreturned`, правильність сум 15000 і 200000 чи включення зборів у підсумок. Два дублікати одного збору або два записи з нульовими сумами теж задовольнять перевірку.

## 7. Денний ліміт перевіряється для однієї поїздки замість накопиченої суми

- **Файл:рядок:** `app/test/unit/tariff.test.js:72–76`
- **Тест:** `the daily cap limits the time charge`
- **Запах:** Wrong oracle / lost intermediate results.
- **Чому це проблема:** З трьох розрахунків зберігається лише останній, а перевіряється `last.total <= DAY_CAP`. Кожна 80-хвилинна поїздка на електровелосипеді коштує 12000, що вже менше за ліміт 30000. Якщо повністю прибрати облік попередніх поїздок, остання коштуватиме 12000 і тест залишиться зеленим, хоча за день буде нараховано 36000. За коректного накопичення третя поїздка має коштувати 6000.

## 8. Записана сума не перевіряється точно

- **Файл:рядок:** `app/test/unit/day-cap.test.js:7–8`
- **Тест:** `charges recorded for a day reduce what is left of the cap`
- **Запах:** Weak assertion.
- **Чому це проблема:** Після запису 12000 перевіряється лише зменшення залишку відносно `DAY_CAP`. Списання однієї копійки, подвійне списання або навіть від’ємний залишок задовольнять нерівність. Правильний залишок 18000 не перевіряється.

## 9. Кількість рядків чека підміняє перевірку кожної статті

- **Файл:рядок:** `app/test/unit/receipt-format.test.js:19–20`
- **Тест:** `a receipt has a line for every item`
- **Запах:** Count-only assertion / incomplete oracle.
- **Чому це проблема:** Перевіряються п’ять рядків і підрядок суми в останньому. Порожні або дубльовані проміжні рядки, неправильна тривалість, назви статей, суми збору та знак знижки залишаться непоміченими. Назва тесту обіцяє перевірити відображення кожної статті, але їхній вміст не зіставляється з вхідними даними.

## 10. Два незалежні маршрути об’єднані в один тест

- **Файл:рядок:** `app/test/unit/server.test.js:29–35`
- **Тест:** `GET / serves the page and GET /api/health answers`
- **Запах:** Eager Test — кілька незалежних сценаріїв в одному тесті.
- **Чому це проблема:** В одному тесті перевіряються HTML-сторінка та health API з різними контрактами. Падіння перевірки сторінки не дасть виконати перевірку health API; звіт не показуватиме незалежний результат для кожного маршруту. Їх можна запускати й діагностувати окремо.

## 11. Неповна перевірка HTTP-контрактів

- **Файл:рядок:** `app/test/unit/server.test.js:31–35`
- **Тест:** `GET / serves the page and GET /api/health answers`
- **Запах:** Incomplete oracle.
- **Чому це проблема:** Для `/` не перевіряється тіло, хоча в `call` передано конкретну функцію `page`; порожня сторінка зі статусом 200 та HTML-заголовком пройде. Для `/api/health` перевіряється лише JSON-тіло: статус 500 або неправильний `content-type` із тим самим тілом теж не спричинять падіння тесту.

## 12. Обіцяна перевірка чека зведена до суфікса підсумку

- **Файл:рядок:** `app/test/unit/server.test.js:45–46`
- **Тест:** `POST /api/quote returns the quote and the receipt`
- **Запах:** Weak assertion / incomplete oracle.
- **Чому це проблема:** Для чека перевіряється лише те, що останній елемент закінчується на `50,00 грн`. Масив з єдиного рядка `50,00 грн` також пройде, хоча не міститиме тривалості та погодинного нарахування. Тест не підтверджує, що API повертає повноцінний чек для отриманого розрахунку.

## 13. Будь-яка доменна помилка зараховується як очікуване відхилення

- **Файл:рядок:** `app/test/unit/tariff.test.js:87`
- **Тест:** `a return before the pickup is rejected`
- **Запах:** Overly broad exception assertion / exception handling smell.
- **Чому це проблема:** `assert.throws(..., QuoteError)` перевіряє лише клас. У `quote` той самий клас використовується для різних помилок: часу, велосипеда, станції та користувача. Якщо валідна частина цих даних почне помилково відхилятися раніше за перевірку порядку дат, тест пройде з неправильної причини. Повідомлення `returnAt is before pickupAt` не перевіряється.

## Перевірка

Запуск `node --test app/test/unit/*.test.js`: **18 тестів, 18 успішних**. Успішне виконання не спростовує перелічених запахів: вони стосуються того, які регресії тести здатні виявити. Код застосунку й тести не змінювалися.
