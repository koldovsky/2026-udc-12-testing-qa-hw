## Прогін 1141 — дефект тесту

**Що впало.** Новий тест із PR впав на першому ж прогоні:

```
ci/runs/run-1141.log:182  ✖ a ride on the night the clocks go back is billed by the station clock
ci/runs/run-1141.log:183  AssertionError: tariff.quote() miscounts the ride across the DST change
ci/runs/run-1141.log:185  180 !== 120   (actual: 180, expected: 120)
```

**Чому.** PR (`ci/changes/run-1141.diff`) додає лише тест, код не чіпає:

```js
// 02:30 → 04:30 on the station clock
const result = quote(ride("2026-10-25T02:30:00+03:00", "2026-10-25T04:30:00+02:00"), { type: "standard" });
assert.equal(result.minutes, 120, ...);
```

Обидві мітки часу мають явний зсув, тож це моменти часу, а не покази настінного
годинника. Фактична тривалість поїздки:

```
$ node -e "const p=Date.parse('2026-10-25T02:30:00+03:00'), r=Date.parse('2026-10-25T04:30:00+02:00'); \
  console.log((r-p)/60000, new Date(p).toISOString(), new Date(r).toISOString())"
180 2026-10-24T23:30:00.000Z 2026-10-25T02:30:00.000Z
```

Поїздка реально тривала 3 години (о 04:00 EEST годинник переводять на 03:00 EET, тож
«02:30 → 04:30 на станційному годиннику» — це 180 реальних хвилин). `quote()` рахує
саме фізичну тривалість (`rideMinutes` у `app/src/tariff.js:70-72`), що відповідає
контракту модуля: «pickupAt / returnAt — ISO 8601 date-time with Z or an offset»
(`app/src/tariff.js:5`). Очікування 120 хв означало б, що клієнт платить за 2 години з
3 проїханих. Локальне відтворення: після `git apply ci/changes/run-1141.diff` тест
падає саме з `180 !== 120`; другий тест із цього ж PR (вечір напередодні) — зелений.

**Клас.** Дефект тесту: хибне очікування (нерозуміння семантики ISO-міток зі зсувом у
ніч переведення годинника). Код працює за контрактом.

**Що виправити.** У `app/test/unit/clock-change.test.js` очікувати фізичну тривалість:
`minutes === 180`, `timeCharge === 6 * 2500` (6 блоків по 30 хв). Якщо продукт справді
хоче білінг «за станційним годинником», це питання до специфікації (`docs/spec/tariffs.md`)
— але тоді у ніч переведення вперед клієнта переплачували б; поточна поведінка коду
коректна й змінювати її не треба.

## Прогін 1144 — нестабільний тест (корінь — дефект оракула в тесті)

**Чому.** Зміна з PR (`ci/changes/run-1144.diff`) торкається лише `app/public/index.html`

Справжня причина — у самому тесті `app/test/integration/receipt.test.js:14-15`:

```js

const expected = (Math.floor(minutes / 30) + 1) * PRICE[ride.bike];
```

Оракул тесту повторює тарифне правило неправильно на межі блоку. Код рахує блоки як

кратних 30:

```

30 5000 2500   <-- розбіжність
31 5000 5000
59 5000 5000
60 7500 5000   <-- розбіжність
61 7500 7500
```

Правильні 50,00 грн за 60 хв (2 блоки) підтверджує й юніт-тест «a 45-minute classic
ride costs 50 UAH» (45 хв = ті самі 2 блоки). Дані тесту випадкові й без сіда:
`randomRide()` у `app/test/helpers/factory.js:14-15` тягне тривалість `between(5, 89)`
хв — межу (30 або 60) вона влучає з імовірністю 2/85 на поїздку, тобто
`1 − (83/85)^10 ≈ 21 %` на прогін з 10 поїздок. Локальне відтворення на незміненому
коді (диф 1144 взагалі не застосовувався):

```
$ for i in 1..15: node --test --test-name-pattern "every receipt of a week" test/integration/receipt.test.js
passes: 11, failures: 4 (той самий код, той самий тест, 15 запусків)
  classic, 60 min ...: got "До сплати ... 50,00 грн", expected 75,00 грн
  ebike,   30 min ...: got "До сплати ... 40,00 грн", expected 80,00 грн
```

**Клас.** Нестабільний тест: падає недетерміновано через випадкові дані без сіда, а
корінь — дефект тесту (хибний оракул на межі 30-хвилинного блока). PR-зміна ні до чого.

**Що виправити.** В `app/test/integration/receipt.test.js`: оракул →
`Math.ceil(minutes / 30) * PRICE[ride.bike]`; додатково зробити дані відтворюваними
(сід для `Math.random` або лог сіда у повідомленні), а межові тривалості (30, 60 хв)

`npm audit` упав через DNS (`EAI_AGAIN npm-mirror.example.net`, рядки 132-143) — крок
