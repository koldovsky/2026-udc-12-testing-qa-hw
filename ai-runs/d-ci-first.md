## Прогін 1141 — PR #231 `tests/clock-change-night` — дефект тесту

**Що впало.** Новий тест, який додав сам PR:

```
run-1141.log:181  test at test/unit/clock-change.test.js:8:1
run-1141.log:182  ✖ a ride on the night the clocks go back is billed by the station clock
run-1141.log:183    AssertionError [ERR_ASSERTION]: tariff.quote() miscounts the ride across the DST change
run-1141.log:185    180 !== 120
```

Решта 21 тест зелена (`ℹ tests 22`, `ℹ fail 1`). PR змінює тільки тести:
`ci/changes/run-1141.diff` — це один новий файл `app/test/unit/clock-change.test.js`, у `src/` змін немає.

**Чому це помилка тесту, а не коду.** Тест передає моменти з явними зсувами:

```js
quote(ride("2026-10-25T02:30:00+03:00", "2026-10-25T04:30:00+02:00"), …)
assert.equal(result.minutes, 120, …);
```

- `2026-10-25T02:30:00+03:00` = `2026-10-24T23:30:00Z`
- `2026-10-25T04:30:00+02:00` = `2026-10-25T02:30:00Z`
- між ними **3 години = 180 хв**. О 04:00 EEST годинник переводять на 03:00 EET, тож
  проміжок 03:00–04:00 за місцевим часом проходить двічі.

Велосипед справді був у користувача 180 хв. `quote()` рахує тривалість як різницю двох
моментів часу (`app/src/tariff.js:70-72`, `Date.parse` у `tariff.js:132`), а контракт модуля
прямо вимагає час «ISO 8601 date-time with Z or an offset» (`tariff.js:5`). Тест вимагає
рахувати за різницею показів годинника на станції (04:30 − 02:30). Тоді годину, що
повторюється, не нарахують, і користувач недоплатить за 2 блоки. Повідомлення в assert
(«quote() miscounts») хибне: рахує неправильно саме тест.

Застереження: специфікація тарифів `docs/spec/tariffs.md` (на неї посилаються
`app/README.md` і `tariff.js:1`) у цю теку не потрапила. Висновок тримається на тому, як
визначено `minutes` у коді і як працюють інші тести. Якщо T3 у специфікації справді
вимагає рахувати «за годинником станції», клас зміниться на дефект коду. Такого правила
не знайшов ні в коді, ні в тестах.

**Перевірити:**
`node -e "console.log((Date.parse('2026-10-25T04:30:00+02:00')-Date.parse('2026-10-25T02:30:00+03:00'))/60000)"`
має вивести `180`.

**Що виправити (у PR #231, у тесті):**
- очікувати `minutes === 180` і `timeCharge === 6 * 2500` (6 блоків по 30 хв);
- перейменувати тест і виправити повідомлення, наприклад «a ride on the night the clocks go
  back is billed by the time actually ridden»;
- для повноти: поїздка почалася о 02:30 за Києвом, тобто діє нічна знижка 30 %
  (`NIGHT_UNTIL_HOUR = 6`). Можна перевірити й `total === 10500`
  (15000 − `discount(15000, 30)` = 15000 − 4500).

**Що впало.**

```
run-1144.log:185  test at test/integration/receipt.test.js:11:1
run-1144.log:186  ✖ every receipt of a week of rides ends with the amount due

**Чому тест нестабільний.** Він порівнює код із власною формулою, і ця формула помиляється
на межі блоку. Дані тест бере випадкові.

```
$ rg -n "Math\.floor\(minutes / 30\) \+ 1|between\(5, 89\)|Math\.ceil\(minutes / BLOCK_MINUTES\)|30 min 20 s" app
app\test\helpers\factory.js:15:  const minutes = between(5, 89);

app\test\unit\tariff.test.js:24:test("a ride of 30 min 20 s is billed as one block", () => {
app\test\integration\receipt.test.js:15:    const expected = (Math.floor(minutes / 30) + 1) * PRICE[ride.bike];
```

- Код рахує `ceil(m/30)` блоків. Що 30 хв — це один блок, окремо підтверджує тест
  `tariff.test.js:24` («30 min 20 s is billed as one block»).
- Тест рахує `floor(m/30) + 1`. Для 60 хв це 3 блоки (75,00 грн) замість 2 (50,00 грн), і
  саме це видно в логу. Дві формули розходяться тільки там, де `m` кратне 30.
- `randomRide()` бере тривалість від 5 до 89 хв (85 варіантів) без зерна генератора.
  Збій дають 30 і 60 хв, тобто ймовірність 2/85 на поїздку. На 10 поїздок у тесті:
  1 − (83/85)¹⁰ ≈ **0,21**, тобто тест падає приблизно в кожному п'ятому прогоні на будь-якому коміті.
- Інших розбіжностей немає: старт о 09:00–19:00 за Києвом (`DAY_START` 06:00Z + 0…600 хв),
  тож нічна знижка не діє. Найбільша сума — 3 × 4000 = 12000, менше за `DAY_CAP` = 30000.
  Станції лише `S01–S08`, усі в зоні.

**Перевірити (детерміновано):** у `receipt.test.js` викликати тест із
`randomRides(10, …)`, підставивши поїздку на 60 хв, наприклад
`{ pickupAt: "2026-09-21T06:00:00.000Z", returnAt: "2026-09-21T07:00:00.000Z" }`.
Тест впаде щоразу.

**Що виправити (у тесті, окремим PR; #233 можна зливати):**
- не відтворювати тариф у тесті. Або взяти таблицю фіксованих поїздок з очікуваними сумами,
  обов'язково з межами 5, 29, 30, 31, 60, 89 хв, або хоча б `Math.ceil(minutes / 30)`;
- якщо випадкові дані потрібні, фіксувати зерно (або друкувати його) і явно додавати межові значення;
- поки тест не виправлено, падіння в ньому не означає регресію в PR, тож автоматичний
  перезапуск його не лагодить, а ховає.

## Прогін 1152 — PR #238 `refactor/fees` — дефект коду

**Що впало.**

```

run-1152.log:186  ✖ a bike kept over a day and left outside the zone pays both fees
run-1152.log:189    1 !== 2

Тест (`app/test/unit/tariff.test.js:64-67`) бере поїздку `2026-09-16T07:00Z → 2026-09-18T07:00Z`
(2880 хв > `UNRETURNED_AFTER_MINUTES` = 1440) з поверненням на `X03` (зона `out`,

**Причина — у diff:**

```diff
-  const fees = [];
-  if (zone === "out") fees.push({ code: "out-of-zone", amount: OUT_OF_ZONE_FEE });
-  if (minutes > UNRETURNED_AFTER_MINUTES) fees.push({ code: "unreturned", amount: UNRETURNED_FEE });
-  return fees;
+  if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
+  if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
+  return [];
```

Раніше збори накопичувались, а тепер `return` після першої умови відкидає другий збір. Для
такої поїздки користувач заплатить 150 грн замість 150 + 2000 грн. Doc-коментар, який додав
сам PR, теж вимагає обидва збори: `/** Fees of a ride: T7 out of zone, T8 over 24 h. */`.
Тест правильний, і він зловив регресію.

**Перевірити:** `git apply ci/changes/run-1152.diff`, потім `cd app; node --test test/unit/tariff.test.js`
(має впасти рядок 66), потім `git apply -R ci/changes/run-1152.diff`.

**Що виправити (у PR #238):** повернути накопичення зборів, лишивши хелпер `fee()`:

```js
function feesFor(minutes, zone) {
  const fees = [];
  if (zone === "out") fees.push(fee("out-of-zone", OUT_OF_ZONE_FEE));
  if (minutes > UNRETURNED_AFTER_MINUTES) fees.push(fee("unreturned", UNRETURNED_FEE));
  return fees;
}
```

Тест варто посилити: замість `fees.length === 2` перевіряти коди й суми
(`deepEqual(result.fees.map(f => f.code), ["out-of-zone", "unreturned"])`), щоб регресія на
кшталт «два однакові збори» теж ловилась.
