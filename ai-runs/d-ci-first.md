# Аналіз чотирьох падінь CI

Висновки зроблено за першими спробами в `ci/runs/`, відповідними diff і поточним `app/` (база main). Diff кожного PR розглянуто окремо, без накопичення змін інших PR. Файли `ci/` та `app/` не змінювалися. Згаданої в коді специфікації `docs/spec/tariffs.md` у наданій теці немає; висновки спираються на доступні дані.

| Прогін | Клас падіння | Причина, що зупинила job |
|---|---|---|
| 1141 | Дефект тесту | Очікування тривалості за показами годинника ігнорує різні UTC-зміщення |
| 1144 | Нестабільний тест | Випадкова тривалість потрапила на межу 60 хв, де формула очікування помилкова |
| 1147 | Середовище | Порт 3000 уже зайнятий; smoke звертається до іншого слухача |
| 1152 | Дефект коду | Ранній return у feesFor робить два незалежні збори взаємовиключними |

## 1141 — дефект тесту

**Докази.** `ci/runs/run-1141.log`, час `07:12:08.9130392Z`: `AssertionError [ERR_ASSERTION]: tariff.quote() miscounts the ride across the DST change`; далі `180 !== 120`, `actual: 180`, `expected: 120`; о `07:12:08.9760080Z` — exit code 1 кроку тестів. Smoke не запускався.

`ci/changes/run-1141.diff` додає лише тест, зокрема:

```js
const result = quote(ride("2026-10-25T02:30:00+03:00", "2026-10-25T04:30:00+02:00"), { type: "standard" });
assert.equal(result.minutes, 120, "tariff.quote() miscounts the ride across the DST change");
assert.equal(result.timeCharge, 4 * 2500);
```

Але початок — `2026-10-24T23:30:00.000Z`, кінець — `2026-10-25T02:30:00.000Z`: минуло **180 хвилин**, а не 120. Це випливає безпосередньо з указаних зміщень, незалежно від часового поясу раннера. `app/src/tariff.js:70–75` обчислює різницю абсолютних моментів і кількість блоків через `Math.ceil`. Локальний виклик `quote` для цих даних повернув:

```json
{"minutes":180,"timeCharge":15000,"discounts":[{"code":"night","amount":4500}],"fees":[],"total":10500}
```

**Що виправити.** У новому тесті очікувати `minutes = 180` і `timeCharge = 6 * 2500`; змінити назву/коментар на перевірку фактично минулого часу через зміну зміщення. Нічна знижка впливає на total, але не змінює minutes чи timeCharge. Не переробляти розрахунок на віднімання локальних показів годинника лише через текст assertion: доказів такої продуктової вимоги тут немає. Помилка відтворюється на фіксованих даних, це не нестабільність.

## 1144 — нестабільний тест із дефектом очікування

**Докази.** `ci/runs/run-1144.log:187`:

```text
AssertionError [ERR_ASSERTION]: classic, 60 min from 2026-09-21T08:14:00.000Z: got "До сплати .......................... 50,00 грн", expected 75,00 грн
```

Тестовий крок завершився exit code 1 (`:200`). `app/test/integration/receipt.test.js:13–15` бере `randomRides(10)` і рахує очікування як `(Math.floor(minutes / 30) + 1) * PRICE[ride.bike]`. У `app/test/helpers/factory.js:10–15` використано `Math.random()` без seed, тривалість — ціле число від 5 до 89. На 30 і 60 хвилинах формула додає зайвий блок; решта цього діапазону проходить. Отже, однаковий коміт може пройти або впасти залежно від згенерованих даних. Успішна друга спроба того самого коміту в `ci/README.md` узгоджується з цим механізмом, але сама по собі не була б достатнім доказом.

Diff 1144 змінює лише `app/public/index.html`: CSS `.hint`, `aria-describedby` і текст підказки. Цей integration-тест викликає `quote` та `formatReceipt` без читання HTML, тому зміна сторінки не спричинила цю помилку.

Локально перевірено той самий розрахунок для classic, денного стандартного тарифу та станції S01:

```text
29 min; test expected= 2500 actual= 2500
30 min; test expected= 5000 actual= 2500
31 min; test expected= 5000 actual= 5000
60 min; test expected= 7500 actual= 5000
61 min; test expected= 7500 actual= 7500
```

**Що виправити.** Замінити формулу очікування на `Math.ceil(minutes / 30) * PRICE[ride.bike]` для поточного діапазону фабрики; явно перевіряти 29/30/31 і 59/60/61 хв для обох типів велосипедів. Зробити набір прикладів детермінованим або використовувати фіксований seed із його записом. Якщо розширювати генератор, врахувати окремо безкоштовний старт, знижки й ліміт. Перезапуск без виправлення лише приховує дефект тесту.

**Супутня помилка, не причина червоного job.** У `:132–142` audit має `EAI_AGAIN` до npm-mirror та `ENOAUDIT`, але `:143` прямо каже: `npm audit failed, continue-on-error is set: the job continues`. Після цього запущено npm test. DNS/доступність mirror варто виправити окремо; попередження кешу після тестів також не пояснює падіння.

## 1147 — середовище: конфлікт порту

**Докази.** У `ci/runs/run-1147.log:168–175` тести пройшли (20 тестів, fail 0). Smoke (`:176–182`) запускає `npm start &` і п'ять разів перевіряє `http://127.0.0.1:3000/api/health`. Сервер падає (`:195`):

```text
Error: listen EADDRINUSE: address already in use :::3000
```

Поля помилки (`:206–210`): `code: 'EADDRINUSE'`, `syscall: 'listen'`, `address: '::'`, `port: 3000`. У `:214–218` усі п'ять curl отримують `404`; крок завершується exit code 1 (`:219`). Це узгоджується з відповідями вже наявного слухача, оскільки новий сервер не зміг запуститися. Власника порту лог не встановлює.

Diff 1147 міняє:

```diff
- const port = Number(process.env.PORT ?? 3000);
+ const port = Number.parseInt(process.env.PORT ?? "", 10) || 3000;
```

і рядок повідомлення про запуск. У показаному env smoke є лише `CI: true`; для відсутнього PORT обидва вирази дають 3000 (перевірено локально). Сам лог теж підтверджує спробу слухати 3000. Зміна парсингу не пояснює зайнятий порт. Тести handler працюють без відкриття сокета (`app/test/unit/server.test.js`), тому їхня успішність не перевіряє запуск процесу. Повторне падіння того самого коміту за README не доводить дефект коду: повторюваний конфлікт середовища теж можливий; лог другої спроби не надано.

**Що виправити.** Ізолювати smoke: виділяти вільний порт, передавати його через PORT і використовувати ту саму адресу в curl; найнадійніше — запуск із портом 0 та отримання фактично призначеного порту через `server.address().port`. Контролювати PID/дострокове завершення сервера, прибирати свій процес через trap. Зібрати діагностику слухача (`ss -ltnp`/`lsof`) у момент конфлікту, щоб знайти його джерело. Не обмежувати виправлення збільшенням очікування: сервер уже завершився з EADDRINUSE. Парсинг `PORT=0` новим виразом окремо варто скоригувати, якщо обрано цей спосіб ізоляції, бо `|| 3000` перетворює 0 на 3000.

## 1152 — дефект коду: втрачений збір

**Докази.** `ci/runs/run-1152.log:186–201`: упав тест `a bike kept over a day and left outside the zone pays both fees`, `AssertionError`, `1 !== 2`, actual 1, expected 2. Exit code 1 у `:205`; smoke не запускався.

У `ci/changes/run-1152.diff` два незалежні `fees.push(...)` замінені на:

```js
if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
return [];
```

Для поїздки з тесту (`2026-09-16T07:00:00Z` → `2026-09-18T07:00:00Z`, classic, X03) тривалість 2880 хв, зона out. Перша умова повертає лише `out-of-zone`; перевірка неповернення стає недосяжною. У базовому коді той самий локальний виклик повернув:

```json
{"minutes":2880,"timeCharge":240000,"discounts":[{"code":"day-cap","amount":210000}],"fees":[{"code":"out-of-zone","amount":15000},{"code":"unreturned","amount":200000}],"total":245000}
```

За diff лишається один збір 15000, total стає 45000 замість 245000 копійок. Це конкретна регресія PR на фіксованому прикладі, а не дефект assertion. Попередження про збереження кешу (`:208–209`) виникло вже після падіння тестів.

**Що виправити.** Накопичувати обидва збори незалежно, повертаючи масив після обох умов (можна зберегти helper `fee`). У перевірці комбінованого випадку порівнювати також коди, суми зборів і total, а не лише довжину; перевірити окремі умови та межу рівно 1440 хв / понад 1440 хв. Денний ліміт не повинен прибирати ці збори.

## Локальна перевірка числових доказів

Наведені вище локальні результати отримано без застосування diff до робочих файлів такою командою з кореня теки:

```bash
node --input-type=module <<'JS'

console.log(JSON.stringify(quote({pickupAt,returnAt,bike:'classic',returnStation:'S02'},{type:'standard'})));
for (const minutes of [29,30,31,60,61]) {
  const p=Date.parse('2026-09-21T08:14:00Z');
  const result=quote({pickupAt:new Date(p).toISOString(),returnAt:new Date(p+minutes*60000).toISOString(),bike:'classic',returnStation:'S01'},{type:'standard'});
  console.log(minutes, 'min; test expected=',(Math.floor(minutes/30)+1)*2500,'actual=',result.total);
}
console.log('unset PORT =>',Number(undefined??3000),Number.parseInt(undefined??'',10)||3000);

JS
```

Це цільова перевірка розрахунків бази, а не повтор усіх CI-прогонів. Результат для PR 1152 виведено з його diff; конфлікт порту на hosted-раннері встановлено з логу, локально його власника не досліджено.
