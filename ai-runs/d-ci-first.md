## Тріаж чотирьох падінь CI (тиждень 19–23.10.2026)

### run-1141 — PR #231 `tests/clock-change-night`

**Що впало:** Новий тестовий файл `test/unit/clock-change.test.js`, тест «a ride on the night the clocks go back is billed by the station clock». `assert.equal(result.minutes, 120)` отримує `180`.

**Зміна в PR:** Додано файл `clock-change.test.js` з двома тестами про поїздку в ніч переведення годинника (25.10.2026, перехід EEST→EET). Поїздка: pickup `2026-10-25T02:30:00+03:00`, return `2026-10-25T04:30:00+02:00`.

**Чому падає:** Тест очікує 120 хвилин — «за годинником станції» (02:30→04:30 = 2 години). Але `tariff.js` рахує тривалість як `(returnAt - pickupAt)` в мілісекундах, що дає реальний астрономічний час: 180 хвилин (3 години). Через переведення годинника назад година 03:00–04:00 повторюється, і фактична різниця між мітками часу — 180 хвилин, а не 120. Тест хибно припускає, що код рахує «за стінним годинником», а код рахує реальну тривалість.

**Класифікація:** Дефект тесту.

**Що зробити:** Виправити очікуване значення в тесті: `assert.equal(result.minutes, 180)` і `assert.equal(result.timeCharge, 6 * 2500)`. Або — якщо специфікація вимагає рахувати «за годинником» — зафіксувати прогалину специфікації і узгодити з командою.

### run-1144 — PR #233 `ui/return-hint`

**Що впало:** Інтеграційний тест `test/integration/receipt.test.js`, «every receipt of a week of rides ends with the amount due». Повідомлення: `classic, 60 min from 2026-09-21T08:14:00.000Z: got "До сплати .......................... 50,00 грн", expected 75,00 грн`.

**Зміна в PR:** Тільки UI — `app/public/index.html`: додано CSS-клас `.hint` і підказка `<p>` під полем «Повернення». Жодних змін у логіці тарифікації чи тестах.

**Чому падає:** Тест використовує випадкові дані: генератор обирає тривалість `between(5, 89)` хвилин. Коли випадає рівно 60 хвилин, тест рахує блоки як `Math.floor(60 / 30) + 1 = 3` (очікуване = 75,00 грн), а код — як `Math.ceil(60 / 30) = 2` (фактичне = 50,00 грн). Формули дають різний результат для тривалостей, кратних 30. Це підтверджує README: другий перезапуск того самого коміту пройшов успішно (випали інші випадкові значення).

**Класифікація:** Нестабільний тест (flaky).

**Що зробити:** Виправити формулу очікуваного значення в `receipt.test.js`: замінити `Math.floor(minutes / 30) + 1` на `Math.ceil(minutes / 30)`, щоб формула в тесті збігалася з продакшн-кодом.

### run-1147 — PR #236 `chore/port-parsing`

**Що впало:** Smoke-тест (крок `npm start` + `curl`). Помилка: `Error: listen EADDRINUSE: address already in use :::3000`. Після цього `curl` 5 разів повертає 404, і крок завершується з exit code 1.

**Зміна в PR:** `app/src/server.js` — заміна `Number(process.env.PORT ?? 3000)` на `Number.parseInt(process.env.PORT ?? "", 10) || 3000` і зміна тексту логу. Порт не змінювався.

**Чому падає:** Порт 3000 вже зайнятий іншим процесом на раннері. Це не пов'язано зі зміною в PR — тести пройшли (20/20 pass), тобто код працює коректно. Проблема в тому, що CI-раннер не звільнив порт між кроками або інший процес (можливо, з іншого job) тримає порт. README підтверджує: навіть другий перезапуск впав з тією ж помилкою.

**Класифікація:** Середовище.

**Що зробити:** Виправити smoke-крок у CI: перед `npm start` — `kill -9 $(lsof -ti :3000) 2>/dev/null || true`, або використати динамічний порт (`PORT=0`), або перевіряти зайнятість порту. Зміна в PR коректна, її можна змерджити після виправлення пайплайна.

### run-1152 — PR #238 `refactor/fees`

**Що впало:** Юніт-тест `test/unit/tariff.test.js`, «a bike kept over a day and left outside the zone pays both fees». `assert.equal` отримує `1` замість очікуваного `2` (кількість зборів у `result.fees`).

**Зміна в PR:** Рефакторинг `feesFor()` у `app/src/tariff.js`. Стара версія додавала збори до масиву `fees` послідовно (push…push). Нова — повертає масив при першому ж збігу через ранній `return`:

```javascript
if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
return [];
```

**Чому падає:** Коли поїздка одночасно «поза зоною» (zone === "out") **і** довша за 24 години, новий код повертає тільки перший збір (`out-of-zone`) і ніколи не дістається до перевірки `unreturned`. Стара версія перевіряла обидві умови незалежно і додавала обидва збори до масиву. Рефакторинг зламав логіку для комбінації обох умов.

**Класифікація:** Дефект коду.

**Що зробити:** Повернути логіку накопичення в масив — перевіряти обидві умови незалежно:

```javascript
function feesFor(minutes, zone) {
  const fees = [];
  if (zone === "out") fees.push(fee("out-of-zone", OUT_OF_ZONE_FEE));
  if (minutes > UNRETURNED_AFTER_MINUTES) fees.push(fee("unreturned", UNRETURNED_FEE));
  return fees;
}
```
