## Run 1141

**Клас:** дефект коду.

**Докази.** Лог вказує тест `test/unit/clock-change.test.js:8:1` і повідомляє: `tariff.quote() miscounts the ride across the DST change`; фактичне значення `180`, очікуване `120` (`ci/runs/run-1141.log:181-196`). PR додає поїздку з `02:30 +03:00` до `04:30 +02:00` і явно очікує 120 хвилин (`ci/changes/run-1141.diff`). Це узгоджується з реалізацією `rideMinutes`: вона віднімає абсолютні мілісекунди (`app/src/tariff.js`, функція біля рядка 52), тому враховує повторену годину, тоді як бізнес-правило тесту вимагає різницю показань станційного годинника.

**Що виправити.** Визначити й реалізувати єдину функцію тривалості за station-clock semantics для вхідних локальних часів/offset-ів (зокрема явно обробити перехід назад), і додати тести на обидва боки переходу. Не змінювати очікування тесту на 180 хвилин, якщо саме тарифне правило — “за станційним годинником”.

## Run 1144

**Клас:** нестабільний тест; безпосередній дефект — у тестовому очікуванні, не в зміні застосунку.

**Докази.** Єдиний diff змінює лише HTML/CSS-підказку (`ci/changes/run-1144.diff:1-22`), не тариф. Падіння сталося в `test/integration/receipt.test.js:11:1`: для classic-поїздки тривалістю 60 хвилин отримано 50,00 грн, але тест очікував 75,00 грн (`ci/runs/run-1144.log:185-200`). Команда над кодом тесту показує формулу `expected = (Math.floor(minutes / 30) + 1) * PRICE[...]` (`app/test/integration/receipt.test.js:13-16`): для 60 хвилин вона дає 3 блоки, хоча тарифна реалізація використовує `Math.ceil(minutes / 30)` і дає 2. Саме тому результат залежить від випадкової тривалості `randomRide`; на іншій випадковій вибірці той самий commit може пройти.

**Що виправити.** Прибрати випадковість із перевірки або зафіксувати seed/набір ride-ів; очікування рахувати тією самою граничною семантикою, що й тариф (`Math.ceil(minutes / 30)`, із окремими тестами для 0, 1, 30, 30+ секунд і 60 хвилин). У поточному тесті також слід врахувати правила нічної знижки та daily cap, якщо генератор коли-небудь їх зачепить.
