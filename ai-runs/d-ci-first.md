## 1141 — PR #231, тест про ніч переведення годинника: дефект тесту

**Симптом** (`runs/run-1141.log`, рядки 150, 183–185): впав лише новий тест, 21 з 22
пройшли.

```
✖ a ride on the night the clocks go back is billed by the station clock
AssertionError [ERR_ASSERTION]: tariff.quote() miscounts the ride across the DST change
180 !== 120
```

**Причина.** Тест із `changes/run-1141.diff` подає поїздку
`2026-10-25T02:30:00+03:00` → `2026-10-25T04:30:00+02:00` і чекає `minutes === 120`.
Це різниця показів настінного годинника (04:30 − 02:30). Реальні моменти:

- `02:30+03:00` = `23:30Z` (24.10);
- `04:30+02:00` = `02:30Z` (25.10);
- різниця = 3 год = **180 хв**.

Година 03:00–04:00 за київським часом цієї ночі настає двічі, тому настінна різниця
менша за реальну на годину. `tariff.js` рахує саме різницю моментів:
`rideMinutes = Math.round((returned - pickup) / 60_000)` (рядок 70–72). Заголовок
файла каже, що `pickupAt`/`returnAt` — ISO 8601 «with Z or an offset», тобто це
абсолютні моменти. `kyivTime` (`kyiv-time.js`) використовується лише для нічної знижки
(`kyivTime(pickup).hour < NIGHT_UNTIL_HOUR`), не для тривалості. Код дає 180 коректно
для поданих даних; другий тест файла (21:00–22:00 до зміни часу) проходить.

Другий вираз тесту теж хибний: `timeCharge === 4 * 2500` відповідає 120 хв; для 180 хв
це `6 * 2500` (6 блоків по 30 хв).

**Що виправити.** У тесті: `minutes` → 180, `timeCharge` → `6 * 2500`, і назву/коментар
«billed by the station clock» замінити на «billed by elapsed time». Сам `tariff.js` не
чіпати.

**Застереження.** Якщо за тарифом (T-правило в `docs/spec/tariffs.md`, якого я не бачу)
поїздку справді мають тарифікувати за настінним годинником станції, то це дефект коду, і
тест правий. Ні `tariff.js`, ні решта тестів на це не вказують, тож я вважаю тест
помилкою, але автору PR варто звірити зі специфікацією перед правкою.

## 1144 — PR #233, підказка на сторінці: нестабільний тест

**Симптом** (`runs/run-1144.log`, рядки 154, 187): впав
`every receipt of a week of rides ends with the amount due`.

```
classic, 60 min from 2026-09-21T08:14:00.000Z: got "До сплати .......................... 50,00 грн", expected 75,00 грн
```

Перезапуск того самого коміту пройшов (`ci/README.md`, колонка «Спроби»).

**Зміна не при чому.** `changes/run-1144.diff` торкається лише `app/public/index.html`
(CSS-клас `.hint`, `aria-describedby`, абзац з підказкою). Сторінку цей тест не
читає: `receipt.test.js` викликає `quote` і `formatReceipt`.

**Причина.** Дані тесту випадкові (`test/helpers/factory.js`: `Math.random`,
`minutes = between(5, 89)`), а оракул у тесті неправильний на межах блоків:

```js
// test/integration/receipt.test.js:15
const expected = (Math.floor(minutes / 30) + 1) * PRICE[ride.bike];
```

Код тарифікує `Math.ceil(minutes / 30)` блоків (`tariff.js`, `blocks()`), і це узгоджено
з тестами, що проходять постійно: `quote ... e-bikes are billed at the e-bike rate`
використовує `Math.ceil(result.minutes / BLOCK_MINUTES)`. На 60 хв: код дає 2 блоки
= 5000 коп = 50,00 грн (так і в логу), тест чекає `floor(2)+1 = 3` блоки = 75,00 грн.
Те саме на 30 хв (код 1 блок, тест 2). На інших значеннях `floor+1 == ceil`, тому тест
зазвичай зелений.

Імовірність падіння за прогін: 2 «поганих» тривалості (30, 60) із 85 можливих
(5…89), 10 поїздок → `1 − (83/85)^10 ≈ 21 %`. Це й дає «упало, перезапуск зелений».

Побічне: у цьому ж логу `npm audit` не дістався до реєстру (`getaddrinfo EAI_AGAIN
npm-mirror.example.net`, рядки 132–143). Це шум середовища, крок має
`continue-on-error: true`, на падіння не впливає.

**Що виправити.** В `receipt.test.js` взяти `Math.ceil(minutes / BLOCK_MINUTES)`
(імпорт із `tariff.js`) замість `floor + 1`. Додати детерміновані випадки 30 і 60 хв,
щоб межі перевірялися завжди, а не за збігом випадкових чисел. Бажано також виводити
seed/дані у повідомленні (воно вже друкує `minutes` і `pickupAt`) або зробити генератор
сідованим.

## 1147 — PR #236, `PORT` через `parseInt`: середовище

**Симптом** (`runs/run-1147.log`, рядки 170–171, 195, 214–219): усі 20 тестів
пройшли (`pass 20`, `fail 0`), впав крок smoke:

```
Error: listen EADDRINUSE: address already in use :::3000
    at file:///home/runner/work/veloprokat/veloprokat/app/src/server.js:74:33
curl: (22) The requested URL returned error: 404      (×5)
##[error]Process completed with exit code 1.
```

**Причина.** На порту 3000 раннера вже хтось слухає, і це не наш застосунок: наш
`GET /api/health` повертає 200 `{"status":"ok"}`, а `curl` п'ять разів отримав 404.
Наш процес лише спробував стартувати і впав на `EADDRINUSE`.

Чому це не зміна коду:

- `changes/run-1147.diff` не змінює порт за замовчуванням:
  `Number(process.env.PORT ?? 3000)` → `Number.parseInt(process.env.PORT ?? "", 10) || 3000`.
  Якщо `PORT` не задано (у логу `env:` тільки `CI: true`), обидва варіанти дають 3000.
- Друга зміна — лише текст `console.log`; smoke його не читає.
- Інший образ: прогони 1147 і 1152 ішли на `Version: 20261020.1`, а 1141 і 1144 — на
  `20261013.1` (рядок 12 кожного логу). Образ оновили між 20 і 22.10, збіг у часі з
  появою зайнятого порту.
- Перезапуск того ж коміту теж упав (`ci/README.md`), тобто це не одноразовий збій
  мережі, а стабільна властивість нового образу. Логу другої спроби в теці немає.

Чого я не можу довести: що саме слухає порт 3000 в образі `20261020.1`. У логу цього
немає, а запустити перевірку не було як. Висновок «середовище» спирається на
відсутність зв'язку зі зміною, 404 від чужого процесу й зміну образу.

Побічно: крок smoke має слабке місце, яке й сховало причину: `npm start &` не
перевіряється, а `curl` по порту 3000 міг би «пройти», потрапивши в чужий сервіс, що
відповідає 200.

**Що виправити** (workflow-файл поза цією текою, тому тут лише рекомендація):

1. Запускати smoke на вільному порту, напр. `PORT=38080 npm start &` і
   `curl http://127.0.0.1:38080/api/health`.
2. Запам'ятати PID (`server=$!`) і в циклі перевіряти `kill -0 "$server"`, щоб падіння
   самого застосунку було видно одразу, а не через 5 невдалих `curl`.
3. Дізнатися в команди раннерів / з release notes `ubuntu24/20261020.1`, що
   зайняло 3000.

PR #236 можна зливати щодо коду: зміна коректна. Є дрібна поведінкова різниця, не
пов'язана з падінням: `PORT=0` тепер дає 3000 замість випадкового порту, а
некоректний `PORT` мовчки замінюється на 3000.

## 1152 — PR #238, спрощення `feesFor`: дефект коду

**Симптом** (`runs/run-1152.log`, рядки 170, 185–201): впав
`a bike kept over a day and left outside the zone pays both fees`.

```
test at test/unit/tariff.test.js:64:1
AssertionError ... 1 !== 2     (actual: 1, expected: 2)
    at ... app/test/unit/tariff.test.js:66:10
```

**Причина.** Рефакторинг змінив поведінку. Було (`app/src/tariff.js`, 105–110):

```js
const fees = [];
if (zone === "out") fees.push({ code: "out-of-zone", amount: OUT_OF_ZONE_FEE });
if (minutes > UNRETURNED_AFTER_MINUTES) fees.push({ code: "unreturned", amount: UNRETURNED_FEE });
return fees;
```

Стало (`changes/run-1152.diff`):

```js
if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
return [];
```

Два незалежні `if` стали ланцюжком із раннім `return`: коли поїздка поза зоною, збір
«неповернений» уже не додається. Тест подає поїздку `2026-09-16T07:00Z → 2026-09-18T07:00Z`
(2880 хв > 1440) на станцію `X03`, яка за `zones.js:14` має `zone: "out"`, тож очікує
обох зборів і отримує один. Тест правий: його назва й коментар у новому JSDoc
(«T7 out of zone, T8 over 24 h») описують два збори, що діють разом. Крім того, це
фінансова похибка: клієнт недоплачує 2000,00 грн (`UNRETURNED_FEE = 200000` коп).

У цьому ж логу `npm audit` не досяг реєстру (`connect ETIMEDOUT 192.0.2.41:443`,
рядки 132–143): шум середовища, `continue-on-error`, на результат не впливає.

**Що виправити.** Повернути накопичення обох зборів, зберігши бажаний стиль:

```js
function feesFor(minutes, zone) {
  const fees = [];
  if (zone === "out") fees.push(fee("out-of-zone", OUT_OF_ZONE_FEE));
  if (minutes > UNRETURNED_AFTER_MINUTES) fees.push(fee("unreturned", UNRETURNED_FEE));
  return fees;
}
```

(або взагалі прибрати `fee` і лишити початковий код). Зі спроби «спростити» варто
залишити JSDoc.
