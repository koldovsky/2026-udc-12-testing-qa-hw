# Тест-кейси розрахунку вартості поїздки (виведені з коду `app/src/`)

## Важливе застереження щодо джерела очікувань

Специфікацію (`docs/spec/tariffs.md`, на яку посилаються коментарі в коді) я **не читав** — за умовою
дозволено лише `app/src/`. Тому **кожне очікування нижче — це те, що робить код зараз**, а не
те, що вимагають правила тарифу. Такі тести зафіксують поточну поведінку, і помилки в коді вони
ловитимуть лише як регресії. Якщо код розходиться зі специфікацією, ці тести «узаконять» помилку.

Місця, де поведінка коду виглядає сумнівною і її треба звірити зі специфікацією, позначено **⚠** і
зібрано в кінці документа (розділ «Що звірити зі специфікацією»).

Позначення джерел: `tariff.js:N` — рядок коду; T3/T6/T9 — номери правил, згадані в коментарях
коду (самих правил я не бачив).

## Від чого залежить результат (за кодом)

`quote(ride, rider, { zones, dayCap })` (`tariff.js:40`) залежить від:

| Вхід | Вплив |
|---|---|
| `ride.pickupAt`, `ride.returnAt` (ISO 8601 зі `Z` або зсувом) | тривалість = `Math.round((return − pickup) / 60 000)` хв (`tariff.js:70-72`); година взяття за Києвом → нічна знижка (`tariff.js:50`); дата взяття **за UTC** → день для денного ліміту (`day-cap.js:6-8`) |
| `ride.bike` | ставка за блок 30 хв: classic 2500, ebike 4000 (`tariff.js:18-19`) |
| `ride.returnStation` | зона `in`/`out` → збір 15000 за повернення поза зоною (`zones.js`, `tariff.js:107`) |
| `rider.type`, `rider.concession` | абонемент / пільга, вибір вигіднішої знижки (`tariff.js:89-98`); пільга також ділить збори навпіл (`tariff.js:63-65`) |
| `rider.id` + `dayCap` (журнал) | денний ліміт 30000 на суму нарахувань за день (`day-cap.js`, `tariff.js:56-61`); без журналу ліміт 30000 застосовується до кожної поїздки окремо |
| `zones` | таблиця станцій (за замовчуванням `stationZones`) |

Порядок розрахунку (`tariff.js:44-67`):
1. `timeCharge` = 0, якщо хвилин < 2; інакше `ceil(хв/30) × ставка` (безкоштовний старт не віднімається від тривалості).
2. Знижка тарифного плану — найбільша з: абонемент (`timeCharge − ceil(max(0, хв−45)/30) × ставка`, для ebike ще −20%), пільга (50% від `timeCharge`). За рівності перемагає той, що раніше у списку (none → subscription → reduced), бо порівняння строге `>`.
3. Нічна знижка 30% від залишку, якщо залишок > 0 і година взяття за Києвом < 6.
4. Денний ліміт: залишок обрізається до доступного ліміту (30000 або залишок у журналі).
5. Збори (поза зоною 15000, неповернений 200000 при > 1440 хв) додаються **після** ліміту; при плані `reduced` кожен збір зменшується на 50%.
6. Округлення знижок (T9): `discount(a, p) = a − floor(a × (100 − p) / 100)` — до сплати округлюється вниз, знижка — вгору.

## Значення за замовчуванням у кейсах

Якщо в кейсі не сказано інше:

- `pickupAt = 2026-01-15T10:00:00+02:00` (10:00 за Києвом, зимовий час, денна поїздка);
- `returnAt = pickupAt + N хв` (N указано в кейсі);
- `bike = "classic"`, `returnStation = "S01"` (зона `in`);
- `rider = { type: "standard" }`, `concession` відсутній;
- `zones = stationZones`, `dayCap` не передається (як у `server.js:33`).

Очікуваний результат — `total` у копійках; у дужках — ключові проміжні поля (`timeCharge`, `discounts`, `fees`), які варто перевіряти теж.

## Що звірити зі специфікацією

Ці місця — не доведені помилки, а розбіжності або неочевидні рішення, які я бачу в коді, але не можу
перевірити без `docs/spec/tariffs.md`. Очікування у відповідних кейсах слід переглянути, коли
специфікацію буде звірено.

1. **⚠1 Безкоштовний старт (A-02, A-03).** Безкоштовні лише поїздки до 1 хв включно (`< 2`); поїздка
   у 2 хв оплачується повним блоком, і ці 2 хв не віднімаються від тривалості. Якщо правило звучить як
   «перші 2 хв безкоштовні» або «до 2 хв включно», очікування для N = 2 буде іншим (0).
2. **⚠2 Округлення тривалості (A-08…A-11).** Хвилини рахуються через `Math.round` (до найближчої), тому
   30:30 уже дає другий блок, а 1:29 — безкоштовно. Специфікація може вимагати округлення вгору або вниз.
3. **⚠3 Вибір «вигіднішого» плану (C-05, F-11, F-12).** Коментар `tariff.js:88` каже «whichever leaves
   the rider less to pay», але порівнюється лише знижка з часу, без урахування того, що пільга ще й
   ділить навпіл збори. У F-11 код бере абонемент і райдер платить 15000, хоча з пільгою заплатив би
   8750 (1250 + 7500); у F-12 — 17500 замість 10000. За рівності (C-05) обирається абонемент — теж через
   це.
4. **⚠4 Денний ліміт в API (E-06).** `server.js` не передає `dayCap`, тож ліміт 30000 діє на кожну
   поїздку окремо, а не на день. Якщо T6 — ліміт на добу на райдера, API його не забезпечує.
5. **⚠5 День для ліміту — за UTC (E-19).** Нічна знижка бере годину за Києвом (`kyiv-time.js`), а
   день для ліміту — `toISOString()`, тобто за UTC. Поїздки, взяті з 00:00 до 02:00 (взимку) /
   03:00 (влітку) за Києвом, потрапляють у попередній день. Якщо день має бути київським, очікування
   для другої поїздки в E-19 — **1750**, а не 0.
