# Тест-кейси розрахунку вартості поїздки

Очікування виведено лише з `app/src/`. Це характеристика поточної реалізації, а не підтвердження відповідності зовнішнім тарифним вимогам. Згадані в коментарях специфікації не читалися. Усі суми — цілі копійки; очікуваний результат — `quote(...).total`, якщо не зазначено помилку. Кейси не запускалися.

## Повні вхідні дані та позначення

Кожен незалежний кейс успадковує базу **B**; стовпець «Вхідні дані» містить усі її зміни:

- `ride = {pickupAt: "2026-01-15T10:00:00Z", returnAt: "2026-01-15T10:30:00Z", bike: "classic", returnStation: "S01"}`.
- `rider = {type: "standard"}`; `concession` та `id` відсутні.
- Опції: `{zones: stationZones}` зі штатною таблицею `app/src/zones.js:3–15`; `dayCap` відсутній. S01–S08 мають зону `in`, X01–X03 — `out`.
- `d` — точна фактична тривалість: `returnAt` дорівнює `pickupAt + d` в абсолютному часі. Наприклад, `d=30 хв 1 с` задає `returnAt="2026-01-15T10:30:01Z"`. Це однозначне задання обох часових входів, включно із секундами.
- `P=...` замінює `pickupAt`; повернення знову обчислюється через `d` (за відсутності `d` — через базові 30 хв).
- `R` означає `rider={type:"reduced"}`; `S` — `{type:"subscriber"}`; `SC` — `{type:"subscriber",concession:true}`.
- Для кейсів із реєстром: новий `createDayCap()` з лімітом 30000, якщо не задано інше; `rider.id="r1"`. Попередні записи явно наведено у відповідному рядку. Між незалежними кейсами стан не переноситься.

## Межі очікувань

- Кожен числовий кейс має перевіряти також узгодженість результату: `total = timeCharge − сума(discounts.amount) + сума(fees.amount)` (`tariff.js:44–67`). Для P13 і F13 важливо перевірити вибраний код плану, оскільки саме він визначає зменшення зборів.
- Реалізація округлює залишок після процентної знижки вниз до копійки (`tariff.js:100–102`). На штатних ставках і зборах у наведених кейсах дробових копійок не виникає; окремо перевірити допоміжну функцію можна входом `discount(101,30)`: результат знижки 31 коп., залишок до сплати 70 коп. Це не самостійна поїздка.
- HTTP-обробник передає до `quote` лише `zones`, без `dayCap` (`server.js:21–34`). Отже, C05–C14 перевіряють прямий виклик функції з реєстром; через штатний API накопичення між запитами немає. Два однакові API-запити B з d=180 хв дадуть по 15000 коп. кожен, незалежно від попередніх запитів (`tariff.js:56`).
