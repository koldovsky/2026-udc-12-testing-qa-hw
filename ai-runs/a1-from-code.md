# Тест-кейси: розрахунок вартості поїздки (A1, з коду)

Джерело очікувань — **лише код** у `app/src/` (насамперед `app/src/tariff.js`,
`app/src/day-cap.js`, `app/src/kyiv-time.js`, `app/src/zones.js`). Специфікацію
`docs/spec/tariffs.md`, на яку посилаються коментарі, не читано — всі очікування
виведені з констант і логіки коду. Усі суми — **в копійках**.

## Модель розрахунку, виведена з коду (`app/src/tariff.js`)

1. `minutes = Math.round((returnAt − pickupAt) / 60_000)` (рядки 70–72).
2. `timeCharge`: `0`, якщо `minutes < FREE_START_MINUTES (2)`; інакше
   `ceil(minutes / 30) × RATE` (`classic` 2500, `ebike` 4000) — рядки 18–20, 74–81.
3. План знижки — найбільша з доступних (рядки 89–98):
   - `subscription` (для `type: "subscriber"`): `timeCharge − blocks(max(0, minutes − 45)) × RATE`;
     для `ebike` плата після 45 хв додатково −20 % (рядки 83–86);
   - `reduced` (для `type: "reduced"` або `subscriber` з `concession: true`): 50 % від `timeCharge`.
4. Нічна знижка 30 % від залишку `due`, якщо `due > 0` і **київська** година
   початку (`kyivTime(pickup).hour`) `< 6` (рядки 50–54, `kyiv-time.js`).
5. Денний ліміт: `due` зрізається до `allowance` (без ledger — стала
   `DAY_CAP = 30000`, `day-cap.js:3`); з ledger — до залишку ліміту рейдера за
   день (рядки 56–61). День визначається за **UTC**-датою `pickupAt`
   (`day-cap.js:6–8`, `toISOString().slice(0,10)`).
6. Збори: `out-of-zone` 15000, якщо станція повернення в зоні `"out"`;
   `unreturned` 200000, якщо `minutes > 1440` (рядки 26–28, 105–110). Якщо
   обраний план — саме `reduced`, кожен збір зменшується на 50 % (рядки 63–65).
   Збори додаються **після** денного ліміту (рядок 66).
7. Округлення знижок: `discount(amount, p) = amount − floor(amount × (100 − p) / 100)` —
   до сплати округлюється вниз до копійки (рядки 101–103).
8. `total = due + Σ fees` (рядок 66).

Якщо не зазначено інше, у кейсах нижче: `rider = { type: "standard" }`,
`returnStation = "S01"` (зона `in`, `zones.js`), опція `zones` — типова
(`stationZones`), `dayCap` не передається, час початку — день (не ніч) за Києвом,
листопад (Київ = UTC+2).

## A. Базове погодинне нарахування

### TC-01 — один тарифний блок
- **Що перевіряє:** базову ціну за 1 блок ≤ 30 хв, classic.
- **Вхідні дані:** `ride = { pickupAt: "2026-11-10T10:00:00+02:00", returnAt: "2026-11-10T10:30:00+02:00", bike: "classic", returnStation: "S01" }`, `rider = { type: "standard" }`.
- **Очікуваний результат:** `minutes = 30`, `timeCharge = 2500`, `discounts = []`, `fees = []`, **`total = 2500`**.
- **Джерело:** `RATES.classic = 2500`, `BLOCK_MINUTES = 30` (`tariff.js:18–19`); `ceil(30/30) = 1` блок.

### TC-02 — межа блоку: 31-ша хвилина відкриває другий блок
- **Вхідні дані:** як TC-01, але `returnAt: "2026-11-10T10:31:00+02:00"` (31 хв).
- **Очікуваний результат:** `minutes = 31`, `timeCharge = 5000`, **`total = 5000`**.
- **Джерело:** `blocks = Math.ceil(31/30) = 2` (`tariff.js:74–76`); 2 × 2500.

### TC-03 — кілька блоків
- **Вхідні дані:** як TC-01, але 61 хв (`returnAt: "2026-11-10T11:01:00+02:00"`).

- **Джерело:** `ceil(61/30) = 3` блоки × 2500.

- **Вхідні дані:** як TC-01, але `bike: "ebike"`, 30 хв.
- **Очікуваний результат:** `timeCharge = 4000`, **`total = 4000`**.
- **Джерело:** `RATES.ebike = 4000` (`tariff.js:18`).

### TC-06 — межа безкоштовного старту: рівно 2 хв уже платні
- **Вхідні дані:** як TC-01, але `returnAt: "2026-11-10T10:02:00+02:00"` (2 хв).
- **Очікуваний результат:** `minutes = 2`, `timeCharge = 2500`, **`total = 2500`**.
- **Джерело:** `tariff.js:79` — умова строга (`<`), тож 2 хв = 1 блок.

- **Вхідні дані:** `pickupAt = returnAt = "2026-11-10T10:00:00+02:00"`, інше як TC-01.
- **Очікуваний результат:** `minutes = 0`, `timeCharge = 0`, **`total = 0`** (помилки немає: заборонено лише `returned < pickup`, `tariff.js:116`).

## D. Абонемент із пільгою (concession): береться дешевший план

### TC-16 — коротка поїздка: перемагає абонемент, збір НЕ зменшується
- **Що перевіряє:** вибір плану з більшою знижкою і те, що зниження збору прив'язане саме до плану `reduced`.
- **Вхідні дані:** 30 хв, classic, `returnStation: "X01"`, `rider = { type: "subscriber", concession: true }`, день.
- **Очікуваний результат:** знижка `subscription = 2500` (повний `timeCharge`; бо 2500 > пільгових 1250), `due = 0`; `fees = [{ code: "out-of-zone", amount: 15000 }]` — **повний** збір; **`total = 15000`**.
- **Джерело:** `cheaperPlan` бере план з max `amount` (`tariff.js:89–98`); зменшення збору лише при `plan.code === "reduced"` (`tariff.js:63–65`).

### TC-17 — довга поїздка: перемагає пільга, збір зменшено
- **Вхідні дані:** 600 хв (`08:00+02:00` → `18:00+02:00`), classic, `returnStation: "X01"`, `rider = { type: "subscriber", concession: true }`.
- **Очікуваний результат:** `timeCharge = 50000` (20 блоків); subscription дала б лише 2500 (`blocks(555) = 19` → 47500), пільга — 25000 → план `reduced`, `due = 25000` (< ліміту 30000); збір `out-of-zone = 7500`; **`total = 32500`**.
- **Джерело:** `tariff.js:89–98` (вибір max), `63–65` (половина збору), розрахунок з констант.

### TC-27 — ledger: друга поїздка за день упирається в залишок ліміту
- **Вхідні дані:** `dayCap = createDayCap()`, `rider = { type: "standard", id: "r-1" }`; поїздка 1: `pickupAt: "2026-11-10T08:00:00Z"`, 300 хв, classic, S01 (через той самий `quote` з цим ledger); поїздка 2: `pickupAt: "2026-11-10T14:00:00Z"`, 300 хв, classic, S01.

### TC-28 — «доба» ліміту визначається за UTC-датою pickup, не за київською
- **Що перевіряє:** зафіксовану в коді поведінку: `dayKey` бере UTC-дату (`toISOString`), тож поїздка о 01:00 за Києвом належить до «вчорашнього» дня UTC.
- **Вхідні дані:** той самий ledger і `rider = { type: "standard", id: "r-1" }`; поїздка 1: `pickupAt: "2026-11-10T20:00:00Z"`, 300 хв, classic, S01; поїздка 2: `pickupAt: "2026-11-11T01:00:00+02:00"` (= `2026-11-10T23:00Z`), 300 хв, classic, S01.
- **Очікуваний результат:** обидві бронюються на день `2026-11-10`. Поїздка 1: **`total = 25000`**. Поїздка 2: `timeCharge = 25000`; нічна (01:00 Київ): `−7500` → `due = 17500`; залишок ліміту 5000 → `day-cap = 12500`; **`total = 5000`**.
- **Джерело:** `dayKey` (`day-cap.js:6–8`); нічна — `tariff.js:50–54`. (Очікування «за кодом»; якщо специфікація вимагає київську добу — це кандидат у баг-репорт.)

### TC-29 — порядок: нічна знижка застосовується ПЕРЕД лімітом
- **Вхідні дані:** `pickupAt: "2026-11-10T03:00:00+02:00"`, 1200 хв (повернення 23:00+02:00), classic, S01, standard, без ledger.
- **Очікуваний результат:** `timeCharge = 100000` (40 блоків); `night = 30000` → `due = 70000`; `day-cap = 40000` → `due = 30000`; **`total = 30000`**.
- **Джерело:** послідовність у `quote` (`tariff.js:50–60`).

- **Вхідні дані:** 1441 хв (`2026-11-10T10:00:00+02:00` → `2026-11-11T10:01:00+02:00`), classic, S01, standard.
- **Очікуваний результат:** `timeCharge = 122500` (49 блоків); `day-cap = 92500` → `due = 30000`; `fees = [{ code: "unreturned", amount: 200000 }]`; **`total = 230000`**.
- **Джерело:** `UNRETURNED_FEE = 200000`, `UNRETURNED_AFTER_MINUTES = 1440`, строга умова `minutes > 1440` (`tariff.js:27–28, 108`); суму 230000 підтверджує і приклад у коментарі `receipt.js:14`.

### TC-32 — межа: рівно 1440 хв — збору немає
- **Вхідні дані:** рівно 1440 хв (`10:00+02:00` → наступний день `10:00+02:00`), classic, S01, standard.
- **Очікуваний результат:** `timeCharge = 120000` (48 блоків) → `due = 30000` (ліміт); `fees = []`; **`total = 30000`**.
- **Джерело:** `tariff.js:108` — умова строга (`>`).

### TC-33 — неповернений + пільга: збір теж −50 %
- **Вхідні дані:** 1441 хв (як TC-31), classic, S01, `rider = { type: "reduced" }`.
- **Очікуваний результат:** `timeCharge = 122500`; `reduced = 61250` → `due = 61250`; `day-cap = 31250` → `due = 30000`; збір `unreturned = 100000`; **`total = 130000`**.
- **Джерело:** `tariff.js:63–65` (половина збору при плані `reduced`), `101–103` (floor).

## H. Помилки валідації (очікується `QuoteError`; через `POST /api/quote` — HTTP 400)

### ERR-01 — повернення раніше за початок
- **Вхідні дані:** `pickupAt: "2026-11-10T10:00:00+02:00"`, `returnAt: "2026-11-10T09:00:00+02:00"`, classic, S01, standard.
- **Очікуваний результат:** `QuoteError("returnAt is before pickupAt")` — суми немає.
- **Джерело:** `tariff.js:116`; мапінг на 400 — `server.js:38`.

### ERR-02 — невідомий тип велосипеда
- **Вхідні дані:** валідні часи, `bike: "scooter"`, S01, standard.
- **Очікуваний результат:** `QuoteError("unknown bike type: scooter")`.
- **Джерело:** `tariff.js:117` (`Object.hasOwn(RATES, …)`).

### ERR-03 — невідома станція повернення
- **Вхідні дані:** валідні часи, classic, `returnStation: "S99"`, standard.
- **Очікуваний результат:** `QuoteError("unknown station: S99")`.
- **Джерело:** `tariff.js:118–119`, `zones.js:20–22` (`zoneOf` → `null`).

### ERR-04 — час без зсуву/Z
- **Вхідні дані:** `pickupAt: "2026-11-10T10:00:00"` (без offset), інше валідне.
- **Очікуваний результат:** `QuoteError("pickupAt must be an ISO 8601 date-time with an offset")`.
- **Джерело:** регулярка `ISO_DATE_TIME` вимагає `Z` або `±hh:mm` (`tariff.js:31, 128–131`).

### ERR-05 — синтаксично коректна, але неіснуюча дата
- **Вхідні дані:** `pickupAt: "2026-13-01T10:00:00Z"` (місяць 13), інше валідне.
- **Очікуваний результат:** `QuoteError("pickupAt is not a valid date-time")`.
- **Джерело:** `Date.parse` → `NaN` (`tariff.js:132–133`).

### ERR-06 — невідомий тип рейдера
- **Вхідні дані:** валідний `ride`, `rider = { type: "guest" }`.
- **Очікуваний результат:** `QuoteError("unknown rider type: guest")`.
- **Джерело:** `RIDER_TYPES` (`tariff.js:30, 124`).

### ERR-07 — ledger без rider.id
- **Вхідні дані:** валідний `ride`, `rider = { type: "standard" }` (без `id`), опція `dayCap = createDayCap()`.
- **Очікуваний результат:** `QuoteError("rider.id is required with a daily cap ledger")`.
- **Джерело:** `tariff.js:125`.

## Примітки (поведінка «за кодом», варта звірки зі специфікацією)

- Доба денного ліміту — за **UTC** (`day-cap.js:6–8`), а нічна знижка — за
  **київським** часом (`tariff.js:50`): між 00:00 і 02:00 за Києвом узимку ці
  «доби» не збігаються (див. TC-28).
- Хвилини округлюються `Math.round` (`tariff.js:71`): поїздка 30 хв 29 с коштує
  як 30 хв (1 блок), а 30 хв 30 с — як 31 хв (2 блоки).
- Нічна знижка залежить лише від моменту **початку** поїздки, навіть якщо майже
  вся поїздка припадає на день (TC-29).
