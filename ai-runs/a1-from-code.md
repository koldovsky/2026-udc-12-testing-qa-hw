# Тест-кейси розрахунку вартості поїздки — виведені з коду

Джерело: лише файли `app/src/` (`tariff.js`, `day-cap.js`, `kyiv-time.js`, `zones.js`, `server.js`, `receipt.js`).
Специфікацію (`docs/spec/tariffs.md`), на яку посилаються коментарі в коді, я **не читав** — так було
поставлено завдання. Тому кожне очікування нижче — це те, що **робить код**, а не те, що мало б бути
за правилами тарифу. Кейси, де поведінка коду виглядає сумнівною (може розходитися з наміром),
позначені **⚠** і зібрані в розділі «Спірні місця» в кінці: для них очікування зафіксовано «як у коді»,
і його варто звірити зі специфікацією, перш ніж робити з нього регресійний тест.

Усі очікувані значення я перевірив, викликавши `quote()` з `app/src/tariff.js` (Node, без створення файлів).

## Від чого залежить результат

`quote(ride, rider, { zones, dayCap })` → `{ minutes, timeCharge, discounts[], fees[], total }` (`tariff.js:3-12`).

| Вхід | Вплив |
|---|---|
| `ride.pickupAt`, `ride.returnAt` | тривалість `minutes = round((return − pickup) / 60 000)` (`tariff.js:70-72`); година відбору за Києвом → нічна знижка (`tariff.js:50`, `kyiv-time.js`); UTC-дата відбору → ключ денного ліміту (`day-cap.js:6-8`) |
| `ride.bike` | ставка за блок 30 хв: `classic` 2500, `ebike` 4000 (`tariff.js:18-19`) |
| `ride.returnStation` | зона повернення: `S01–S08` = `in`, `X01–X03` = `out` → збір 15000 (`zones.js:3-15`, `tariff.js:26,107`) |
| `rider.type` | `standard` / `reduced` / `subscriber` (`tariff.js:30`) |
| `rider.concession` | тільки для `subscriber`, тільки строго `true` → дає ще й право на пільговий тариф (`tariff.js:94`) |
| `rider.id` | обов'язковий, якщо передано `dayCap`; ключ леджера (`tariff.js:125`, `day-cap.js:12`) |
| `dayCap` (опц.) | леджер з `createDayCap()`; без нього ліміт 30000 застосовується до кожної поїздки окремо (`tariff.js:56`) |
| `zones` (опц.) | таблиця станцій; за замовчуванням `stationZones` |

Порядок обчислення (`tariff.js:40-68`):
1. `timeCharge` = 0, якщо `minutes < 2`; інакше `ceil(minutes/30) × ставка` (`tariff.js:78-81`).
2. Знижка плану — найбільша з: немає / абонемент / пільговий 50% (`tariff.js:89-98`). При рівності перемагає раніший у списку (none → subscription → reduced), бо порівняння строге `>`.
   - абонемент: перші 45 хв безкоштовні, далі `ceil((minutes−45)/30) × ставка`, для `ebike` ще −20% (`tariff.js:83-86`);
3. Нічна −30% від залишку, якщо залишок > 0 і година відбору за Києвом < 6 (`tariff.js:50-54`).
4. Денний ліміт: залишок обрізається до 30000 (або до `dayCap.remaining`), різниця — знижка `day-cap`; у леджер записується залишок (`tariff.js:56-61`).
5. Збори: поза зоною 15000; неповернений (`minutes > 1440`) 200000; якщо обраний план `reduced` — кожен збір −50% (`tariff.js:63-65,105-110`). Збори не підпадають під нічну знижку й денний ліміт.
6. `total = залишок + збори` (`tariff.js:66`).
7. Округлення відсотків: `discount(a, p) = a − floor(a·(100−p)/100)` — сума до сплати округлюється вниз (`tariff.js:101-103`).

## Значення за замовчуванням у кейсах

Якщо в кейсі не сказано інше:
- `pickupAt = "2026-01-15T10:00:00+02:00"` (зима, Київ = UTC+2, день);
- `returnAt = pickupAt + тривалість` (тривалість указано в колонці «Вхід»; секунди — де важливо);
- `bike = "classic"`, `returnStation = "S01"` (у зоні);
- `rider = { type: "standard" }`, без `concession`;
- `zones` — стандартні, `dayCap` не передано.

Очікуваний результат — `total` у копійках; де важливо, наведено й розклад (`timeCharge`, `discounts`, `fees`).

## 8. Округлення відсоткових знижок (`discount`, експортована)

З тарифними ставками 2500/4000 і відсотками 20/30/50 дробові копійки не виникають, тому округлення

## Спірні місця (⚠) — очікування «як у коді», звірити зі специфікацією

1. **День денного ліміту — дата UTC** (`day-cap.js:7`), а нічна знижка — за київським часом (`kyiv-time.js`).
   Поїздки з 00:00 до 02:00 (взимку) / 03:00 (влітку) за Києвом зараховуються в ліміт попереднього дня (TC-97, TC-98).
2. **«Дешевший план» вибирається лише за знижкою з погодинного нарахування** (`tariff.js:46,89-97`), хоча
   коментар каже «whichever leaves the rider less to pay». Знижка −50% на збори прив'язана до обраного плану
   `reduced`, тож абонент із пільгою з поверненням поза зоною може заплатити більше, ніж за пільговим (TC-75, TC-76).
3. **Пільговий райдер без погодинного нарахування платить збори повністю**: при `timeCharge = 0` план `reduced`
   дає знижку 0 і не перемагає `none` (строге `>`), тому збори не знижуються (TC-73, TC-74, TC-77).
4. **Збір поза зоною за безкоштовний старт** (TC-71) — код не робить винятку для поїздок < 2 хв.
5. **Нічна знижка — лише за часом відбору** (TC-44); поїздка 05:50–09:00 отримує −30% повністю.
6. **Округлення тривалості `Math.round`** (TC-03/04, TC-07/08, TC-67/79): 30 с вирішують, чи буде ще блок
   або збір 2000 грн за неповернення.
7. **Валідація дати пропускає неіснуючі дні** на кшталт 30 лютого (TC-118).
8. **Без леджера ліміт 300 грн діє на кожну поїздку окремо**, а HTTP API леджер не передає (TC-132) — тобто
   через API денний ліміт фактично є лімітом на одну поїздку.
