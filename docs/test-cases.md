# Тест-кейси: розрахунок вартості поїздки (`quote`, чек)

Джерело очікувань — **лише** `docs/spec/tariffs.md` (версія 3, чинна з 2026-09-15). Чернетки
AI (`ai-runs/a1-from-code.md`, `ai-runs/a2-from-spec.md`) використано як підказку, але кожне
число перераховано за специфікацією вручну.

## Умовні позначення

**Вхідні дані:** `категорія · велосипед · взяття → повернення · станція`.

- Категорія: `Ст` — стандартний; `Піл` — пільговий; `Аб` — абонент без права на пільгу;
  `Аб+П` — абонент із правом на пільгу.
- Велосипед: `Кл` — класичний; `Ел` — електровелосипед.
- Час: якщо дату не вказано — **2026-09-16**, київський час, зсув **+03:00** (наприклад,
  `10:00:00 → 10:12:40` = `2026-09-16T10:00:00+03:00 → 2026-09-16T10:12:40+03:00`). Де зсув
  важливий — його вказано явно.
- Станція: якщо не вказано — `S01` (у зоні).
- **Сценарій** — кілька поїздок **одного й того самого користувача** в одній «історії»
  денного ліміту, у порядку взяття; очікування — для кожної поїздки.

**Очікуваний результат** — сума «До сплати» за поїздку в копійках (погодинне після знижок і
ліміту + збори), або «відмова з поясненням» (розд. 4). Розклад наведено, де він потрібен для
розуміння.

Техніки: **EP** — класи еквівалентності; **BVA** — граничні значення; **ТР** — таблиця
рішень (комбінації правил); **СЧ** — стани й час.

Кейси, що залежать від відкритих питань (Q-1…Q-7), сюди **не включено** — вони в розділі
«Питання до специфікації».

## Що AI вигадав

причиною; кількість — у дужках. Не зараховано: точні тексти помилок і HTTP-коди в TC-119…TC-127,
TC-133 (A1) — сама відмова узгоджується з розд. 4.
