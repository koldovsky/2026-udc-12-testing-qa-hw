узгоджується зі специфікацією.

Як рахувалося:

- **Правил покрито.** A1 посилається на рядки коду, тому його кейси зіставлено з T1–T10 за
  тим, що вони перевіряють. Правильні кейси A1: T1 — A-11, A-16, D-13, D-14; T2 — A-01,
  A-02, A-15; T3 — A-04…A-07, A-13, A-14; T4 — B-02…B-06; T5 — C-01…C-09, F-11, F-12;
  T6 — E-01, E-02, E-10…E-17; T7 — F-01…F-04; T8 — F-05…F-07, F-14; T9 — G-01…G-05,
  I-01; T10 — D-05, D-06. A2 має правильні кейси на кожне правило.
- **Очікувань, яких немає в специфікації.** Одиниця — кейс чернетки (його ID). Кейс
  зараховано, якщо його очікування суперечить специфікації або однозначно з неї не
  виводиться (залежить від Q-1…Q-11). Оцінюється очікування з колонки «Очікування»; проміжні
  поля в дужках у A1 (`minutes`, `timeCharge`, `discounts`…) окремо не оцінювались — A1 сам
  пише, що результат кейсу — `total`. Для кейсів про чек чи формат оцінюється вміст чека.
  Число = кількість рядків цієї чернетки в «Що AI вигадав»: A1 — 24, A2 — 3.
  - A1 має 104 кейси. Оцінено 88 — ті, що про суму, тривалість, збори, округлення чи чек.
    Не оцінювались 16 кейсів про поведінку API і валідацію формату: H-01…H-10, E-20,
    I-03…I-07 (HTTP-коди, тексти помилок, регулярний вираз ISO 8601, `__proto__`, розмір тіла).
    Специфікація тут каже лише «відхиляється з поясненням» (`:147-149`): H-01, H-05,
    H-06, H-08 за самим фактом відхилення з нею узгоджуються, а тексти й коди помилок вона
    не визначає (Q-11); решта — формат транспорту, про який специфікація мовчить. B-10,
    B-11, A-12, A-17 оцінено за сумою для вхідних даних так, як їх розуміє A1.
  - Дати A1 (2026-01-15, 2026-03-29, 2026-07-01) — до набрання чинності v3 (`:8`); суворо
    кажучи, тариф для них не визначений (Q-4). Щоб не зарахувати як «вигадане» все підряд,
