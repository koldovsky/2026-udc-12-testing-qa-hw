## Очікуваний результат (за специфікацією)

Поїздка 16.09 10:00 → 18.09 10:00 (2 880 хв), класичний велосипед, станція X03:

- погодинне нарахування за T3: `ceil(2880 / 30) = 96` блоків × 25 грн = 240 000 коп.,
  обмежене денним лімітом T6 до **30 000** коп. (`docs/spec/tariffs.md:100-101`);
- збір за повернення поза зоною T7 — **15 000** коп. (`:112`);
- збір за неповернений велосипед T8 — **200 000** коп. (`:119-120`);
- обидва збори нараховуються незалежно (`:121-122`), збори лімітом не обмежуються (`:103`).

**До сплати: 245 000 коп. (2 450,00 грн), у `fees` — два рядки.**

## Мінімальний вхід

Поїздка, яка одночасно **понад 24 години** і **поза зоною**. Досить змінити станцію
повернення на будь-яку в зоні (`S01`) — і збір T8 з'являється; досить скоротити поїздку до
24 годин — і зникає сам збір T8, тож дефект не видно. Тобто помилку видно лише на перетині
двох умов, і саме тому решта 19 тестів прогону лишилася зеленою.

## Додатково

Місце в коді — `feesFor()` у `app/src/tariff.js` (у стані PR — рядки 105-112). Рефакторинг
замінив накопичення на early-return:

```diff
-  const fees = [];
-  if (zone === "out") fees.push({ code: "out-of-zone", amount: OUT_OF_ZONE_FEE });
-  if (minutes > UNRETURNED_AFTER_MINUTES) fees.push({ code: "unreturned", amount: UNRETURNED_FEE });
-  return fees;
+  if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
+  if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
+  return [];
```

Перший `return` виходить із функції, тому другу умову для поїздки поза зоною вже ніколи не
перевіряють. Зверніть увагу на асиметрію: якщо велосипед не повернули, але залишили **в**
зоні, збір T8 нараховується правильно — тому дефект і не видно на жодному «звичайному»
кейсі.

**Виправлення (що саме змінити):** лишити допоміжну функцію `fee()`, якщо вона подобається
авторові PR, але повернути накопичення обох зборів, наприклад:

```js
function feesFor(minutes, zone) {
  return [
    zone === "out" ? fee("out-of-zone", OUT_OF_ZONE_FEE) : null,
    minutes > UNRETURNED_AFTER_MINUTES ? fee("unreturned", UNRETURNED_FEE) : null,
  ].filter(Boolean);
}
```

Порядок рядків («поза зоною», потім «неповернений») треба зберегти: у такому порядку їх
очікує чек (`app/src/receipt.js:27`) і тест
`app/test/spec/t7-t8-fees.test.js` › `T7 + T8 (TC-39)`.

**Чому цей дефект дійшов до CI, а не до ревʼю.** Наявний тест, який його зловив, перевіряв
лише **кількість** зборів (`assert.equal(result.fees.length, 2)`) — це запах № 5 у
`docs/test-quality.md`. Цього разу слабкої перевірки випадково вистачило, але вона
промовчала б, якби рефакторинг поміняв збори місцями, обнулив суми або переплутав коди. У
цій гілці той самий випадок перевіряється складом і сумами —
`app/test/spec/t7-t8-fees.test.js` › `T7 + T8 (TC-39): класичний, 25 год, станція X03`
(очікування 30000 + 15000 + 200000 = 245000, `docs/test-cases.md`, TC-39).
