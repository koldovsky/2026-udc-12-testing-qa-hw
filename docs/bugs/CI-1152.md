## Кроки відтворення

1. `rm -rf ../ws12-d-repro && mkdir -p ../ws12-d-repro && git archive main app ci | tar -x -C ../ws12-d-repro`
2. `cd ../ws12-d-repro && git init -q && git apply ci/changes/run-1152.diff`
3. `npm --prefix app test` — червоний тест `a bike kept over a day and left outside the zone pays both fees`.
4. Розрахувати поїздку стандартного користувача, класичний, 16.09.2026 10:00 → 17.09.2026 11:00 (25 год), повернення на `X03` — команда нижче.

## Очікуваний результат (за специфікацією)

(`:120`); обидва збори разом (`:121-122`) → **245 000** коп., у `fees` два записи: `out-of-zone` і `unreturned`.

## Фактичний результат

`fees: [{ code: "out-of-zone", amount: 15000 }]`, `total: 45000` — збору T8 немає.

## Мінімальний вхід

Тривалість 1441 хв (понад 24 год) + станція `X01`. Якщо станція в зоні (`S01`), збір T8 нараховується, бо перша
умова не спрацьовує. Якщо тривалість ≤ 1440 хв, другого збору й так немає. Дефект видно лише за обох умов.

## Додатково

- Hunk зі зміни (`ci/changes/run-1152.diff`):

  ```diff
  +  if (zone === "out") return [fee("out-of-zone", OUT_OF_ZONE_FEE)];
  +  if (minutes > UNRETURNED_AFTER_MINUTES) return [fee("unreturned", UNRETURNED_FEE)];
  +  return [];
  ```

  Ранній `return` у першій умові робить дві незалежні умови взаємовиключними. PR названо «спростити feesFor»,
  тобто це рефакторинг, який мав не змінювати поведінку.
- Червоний тест у CI правий, його не чіпати: він перевіряє саме T8 `:121-122`. Але перевіряє лише `fees.length`
  (запах 5 у `docs/test-quality.md`). Тест `T8: TC-45 classic 25 h returned to X03 → both fees` з
  `app/test/spec/t07-t08-fees.test.js` ловить це точним `total` 245000.
- Перша помилка в лозі — `npm error code ENOAUDIT` (`run-1152.log:137`). Це не причина: крок `npm audit` має
  `continue-on-error: true` (`ci/README.md`, `run-1152.log:143`), і job після нього продовжився до `npm test`.
