# BUG-1: неповну хвилину округлює до найближчої, а не вгору — 30 хв 20 с коштують як 30 хв

| Поле | Значення |
|---|---|
| **Правило специфікації** | T1 — «Неповна хвилина рахується як повна: тривалість округлюється вгору до цілих хвилин» (`docs/spec/tariffs.md:46-47`) |
| **Середовище** | `main` = `4606c72` (до виправлення); Node v22.14.0; Windows 11 Pro, Git Bash |
| **Серйозність** | висока. Зачіпає кожну поїздку, у якій неповна хвилина менша за 30 с. Біля межі блока (30:01…30:29, 60:01…60:29, …) користувач недоплачує цілий блок (25 або 40 грн). Біля межі хибного старту (2:01…2:29) поїздку рахує як 2 хв. Поїздку тривалістю 24:00:01 не вважає «понад 24 години», тож збір T8 2 000 грн не нараховано (тест `T8: TC-43`) |
| **Частота** | завжди, якщо дробова частина хвилини < 0,5 |
| **Знайдено** | `app/test/spec/t01-t03-duration-and-hourly.test.js` › `T1: TC-03 30 min 20 s → 31 min, 2 blocks`, `T2: TC-08 2:01 → 3 min → 1 block`; `app/test/spec/t07-t08-fees.test.js` › `T8: TC-43 classic 24:00:01 → fee 200000` (`ai-runs/b2-run.txt`) |
| **Виправлення** | `a9527fd fix(T1): round ride duration up to whole minutes` — `Math.round` → `Math.ceil` у `rideMinutes` (`app/src/tariff.js:70` після виправлення) |

## Кроки відтворення

1. `git archive main app | tar -x -C ../ws12-main && cd ../ws12-main`
2. Розрахувати поїздку стандартного користувача на класичному велосипеді: взяття 16.09.2026 10:00:00, повернення 10:30:20 (Київ), станція `S01` — команда нижче.

## Очікуваний результат (за специфікацією)

30 хв 20 с → неповна хвилина рахується як повна → **31 хв** (T1, `:46-47`) → 2 розпочаті блоки по 30 хв
(T3, `:62`) → `timeCharge` = `total` = **5000** коп.

## Фактичний результат

`minutes: 30`, `timeCharge: 2500`, `total: 2500` — один блок.

## Мінімальний вхід

Тривалість 30:01. Будь-яка тривалість із дробовою частиною < 0,5 хв показує дефект, ≥ 0,5 хв — ні
(`Math.round` випадково збігається з `Math.ceil`). Приклад специфікації 10:00:00 → 10:12:40 (`:49`)
дефекту **не** ловить: 12,67 хв і вниз, і вгору дає 13.

## Додатково

- Місце в коді: `app/src/tariff.js:71` `Math.round((returned - pickup) / 60_000)`.
- Наявний тест `app/test/unit/tariff.test.js` › `a ride of 30 min 20 s is billed as one block` стверджував
  хибну поведінку (30 хв, 2500). Оновлено за T1 — див. `docs/bugs/README.md`.
- Тест AI «з коду» `ai-runs/b1-from-code/tariff.test.js` › `seconds are rounded to the nearest minute`
  зафіксував цей дефект (`ai-runs/b1-rerun.txt`).
