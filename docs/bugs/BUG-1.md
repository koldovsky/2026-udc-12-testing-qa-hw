# BUG-1: неповна хвилина відкидається — поїздку 30 хв 20 с рахують як 1 блок замість 2

| Поле | Значення |
|---|---|
| **Правило специфікації** | T1 — «Неповна хвилина рахується як повна: тривалість округлюється вгору до цілих хвилин» (`docs/spec/tariffs.md:46-47`) |
| **Середовище** | дефект — у `main` (`4606c72`), відтворено на копії `git archive main app`; Node v26.3.0; Windows 10 (Git Bash) |
| **Серйозність** | висока — недобір грошей і хибна тривалість у чеку для кожної поїздки, що закінчується в першій половині хвилини; на межі блоку (30:01–30:29, 60:01–60:29 …) користувач недоплачує цілий блок (25 / 40 грн); на межі 24 год (24:00:01–24:00:29) не нараховується збір T8 2 000 грн |
| **Частота** | завжди, коли залишок секунд < 30 (`Math.round` замість округлення вгору) |
| **Знайдено** | `app/test/spec/tariff.test.js` › `T1: TC-05 30:01 → 31 хв, 2 блоки`, `T2: TC-09 2 хв 1 с → 3 хв → 2500`, `T8: TC-42 24 год 1 с → 1441 хв → 30000 + 200000` (`ai-runs/b2-run.txt`) |
| **Виправлення** | `94763ec fix(T1): round ride duration up to whole minutes` |

## Кроки відтворення

1. З кореня репо на коді з `main` порахувати поїздку класичним велосипедом, стандартний
   користувач, взяття `2026-09-16T07:00:00Z`, повернення `2026-09-16T07:30:20Z`, станція S01
   (команда нижче).
2. Подивитися `minutes`, `timeCharge`, `total`.

## Очікуваний результат (за специфікацією)

30 хв 20 с → неповна хвилина як повна → **31 хв** (T1, `:46-47`) → 2 розпочаті блоки по 30 хв
(T3, `:62`, `:66`) → `timeCharge` = `total` = **5000**.

## Фактичний результат

`minutes: 30`, `timeCharge: 2500`, `total: 2500`.

## Доказ

```bash
node -e 'import("./app/src/tariff.js").then(({ quote }) => console.log(JSON.stringify(quote(
  { pickupAt: "2026-09-16T07:00:00Z", returnAt: "2026-09-16T07:30:20Z", bike: "classic", returnStation: "S01" },
  { type: "standard" }))))'
```

До виправлення (копія `main`):

```text
{"minutes":30,"timeCharge":2500,"discounts":[],"fees":[],"total":2500}
```

Після виправлення (`1b3e725`):

```text
{"minutes":31,"timeCharge":5000,"discounts":[],"fees":[],"total":5000}
```

## Мінімальний вхід

Будь-яка поїздка з залишком 1–29 с понад цілу хвилину; найнаочніше — 30 хв 1 с
(TC-05): 30 замість 31 хв. З залишком ≥ 30 с (наприклад, 30 хв 30 с) `Math.round` випадково
дає те саме, що й округлення вгору, — дефект зникає.

## Додатково

- Місце в коді: `app/src/tariff.js:70-72` (`rideMinutes`) — `Math.round` замість `Math.ceil`.
- Наявний тест `app/test/unit/tariff.test.js` › `a ride of 30 min 20 s is billed as one block`
  стверджував саме дефект (30 хв, 2500); оновлено за специфікацією в коміті виправлення
  (див. `docs/bugs/README.md`).
- Тест з коду `ai-runs/b1-from-code/tariff.test.js` › `minutes are rounded to the nearest
  minute` називає дефектну поведінку прямо («nearest»).
