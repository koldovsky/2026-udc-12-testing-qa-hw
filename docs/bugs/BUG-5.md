# BUG-5: Доба денного ліміту рахується за UTC, а не за київським часом

| Поле | Значення |
|---|---|
| **Правило специфікації** | T6 + терміни — «Доба: календарна дата за київським часом, від 00:00 до 24:00» (`docs/spec/tariffs.md:34`); «Поїздка належить до тієї доби, на яку припадає момент її взяття за київським часом» (`docs/spec/tariffs.md:101-102`) |
| **Середовище** | код з `main` (`4606c72`), Node v24.16.0, Windows 11 (Git Bash) |
| **Серйозність** | середня: для поїздок, узятих із 00:00 до 02:00/03:00 за Києвом (залежно від сезону), ліміт рахується до чужої доби — користувач або безпідставно їздить «безплатно» (вчорашній ліміт вичерпано), або його новий денний ліміт займають учорашні поїздки |
| **Частота** | завжди для взяття між 00:00 і 02:00 (зима) / 03:00 (літо) за Києвом, якщо в суміжні доби є інші нарахування |
| **Знайдено** | `app/test/spec/day-cap.test.js` › `T6: a new day starts at Kyiv midnight — pickup 17.09 00:30 Kyiv (16.09 21:30Z) is charged: 2500 − 30 % (T10) → 1750 (TC-22)` (прогін `ai-runs/b2-run.txt`) |
| **Виправлення** | `1db07ae fix(T6): доба денного ліміту — календарна дата за київським часом` |

## Кроки відтворення

1. Взяти код із `main` (`mkdir -p ../ws12-main && git archive main app | tar -x -C ../ws12-main`).
2. Вичерпати ліміт користувача за 16.09 (три поїздки електро по 2 год або `record(…, 30000)`).
3. Порахувати поїздку того самого користувача з взяттям **17.09 о 00:30 за Києвом** (= 16.09 21:30 UTC).

## Очікуваний результат (за специфікацією)

00:30 17.09 за Києвом — **нова доба** (`docs/spec/tariffs.md:34,101-102`), ліміт
17.09 не чіпався → нараховується: 1 блок 2500 − 30 % нічної знижки (T10) =
**1750 коп.**

## Фактичний результат

`dayKey` відносить взяття до `2026-09-16` (UTC-дата), залишок ліміту 0 →
`total = 0`: поїздка безплатна.

## Доказ

```bash
cd ../ws12-main && node -e 'Promise.all([import("./app/src/tariff.js"), import("./app/src/day-cap.js")]).then(([{ quote }, { createDayCap, dayKey }]) => { console.log("dayKey:", dayKey(Date.parse("2026-09-17T00:30:00+03:00"))); const cap = createDayCap(); cap.record("r-1", Date.parse("2026-09-16T12:00:00+03:00"), 30000); const q = quote({ pickupAt: "2026-09-17T00:30:00+03:00", returnAt: "2026-09-17T01:00:00+03:00", bike: "classic", returnStation: "S03" }, { type: "standard", id: "r-1" }, { dayCap: cap }); console.log(JSON.stringify({ discounts: q.discounts, total: q.total })); })'; cd -
```

```text
dayKey: 2026-09-16
{"discounts":[{"code":"night","amount":750},{"code":"day-cap","amount":1750}],"total":0}
```

Після виправлення: `dayKey: 2026-09-17`, `total = 1750`.

## Мінімальний вхід

`dayKey(Date.parse("2026-09-17T00:30:00+03:00"))` → `"2026-09-16"` замість
`"2026-09-17"`. Візьміть взяття після 03:00 за Києвом — UTC-дата збігається з
київською і дефект зникає.

## Додатково

Причина — `new Date(pickupAt).toISOString().slice(0, 10)` у `dayKey`
(`app/src/day-cap.js:7` на `main`): UTC-дата. Виправлено через
`kyivTime(...).date` (`app/src/kyiv-time.js`). Приклад специфікації (23:40 →
00:20) дефект не ловив, бо 23:40 за Києвом — ще та сама дата і в UTC: межа
розходження — опівніч за Києвом. Тести «з коду»
`ai-runs/b1-from-code/day-cap.test.js` (два тести про UTC-добу) зафіксували
дефект як норму (червоні в `ai-runs/b1-rerun.txt`).
