# BUG-5: поїздка після опівночі за Києвом зараховується до ліміту попередньої доби

| Поле | Значення |
|---|---|
| **Правило специфікації** | §2 «Доба — календарна дата за київським часом» (`docs/spec/tariffs.md:34`); T6 — «Поїздка належить до тієї доби, на яку припадає момент її **взяття** за київським часом» (`:101-102`) |
| **Середовище** | коміт до виправлення: `148b125`; Node v26.3.0; Windows 11 Pro 10.0.26300 |
| **Серйозність** | середня — нічні поїздки 00:00–03:00 за Києвом (влітку; взимку 00:00–02:00) рахуються в ліміт учорашньої доби: якщо вчорашній ліміт вичерпано — поїздка безкоштовна (сервіс недобирає), якщо ні — з'їдає вчорашній залишок, а ліміт нової доби лишається повним |
| **Частота** | за умови: взяття між 00:00 і 03:00 (UTC+3) / 02:00 (UTC+2) за Києвом і облік ліміту через `createDayCap()` |
| **Знайдено** | `app/test/spec/t6-day-cap.test.js` › `T6, T10: TC-39 …` (`ai-runs/b2-run.txt:59`) |
| **Виправлення** | `ec0c832 fix(T6): daily cap day is the Kyiv calendar date of the pickup` |

## Кроки відтворення

1. Створити журнал ліміту `createDayCap()` і записати користувачу U1 30 000 коп. на
   `2026-09-16T07:00:00Z` (16.09 10:00 за Києвом) — ліміт 16.09 вичерпано.
2. Порахувати поїздку U1 (стандартний, класичний, S01) з цим журналом: взяття
   `2026-09-16T22:00:00Z` (**17.09 01:00** за Києвом), повернення `2026-09-16T22:30:00Z`.
3. Подивитися `dayKey` взяття і `total`.

## Очікуваний результат (за специфікацією)

Взяття 17.09 01:00 за Києвом → доба 17.09 (`:34`, `:101-102`) → ліміт новий; уся поїздка в
нічному вікні (`:141`) → 2 500 − 30 % → **1 750 коп.**

## Фактичний результат

`dayKey` → `2026-09-16`; `total` → `0` (поїздку зараховано до вичерпаного ліміту 16.09).

## Доказ

```bash
node -e "import('./app/src/day-cap.js').then(({createDayCap,dayKey})=>import('./app/src/tariff.js').then(({quote})=>{const cap=createDayCap();cap.record('U1','2026-09-16T07:00:00Z',30000);const q=quote({pickupAt:'2026-09-16T22:00:00Z',returnAt:'2026-09-16T22:30:00Z',bike:'classic',returnStation:'S01'},{id:'U1',type:'standard'},{dayCap:cap});console.log(dayKey('2026-09-16T22:00:00Z'),q.total)}))"
```

```text
2026-09-16 0
```

## Мінімальний вхід

`dayKey('2026-09-16T22:00:00Z')` → `2026-09-16` замість `2026-09-17`. О `2026-09-16T21:00:00Z`
(16.09 24:00 ≡ 17.09 00:00 за Києвом) — теж 16.09; о `2026-09-17T00:00:00Z` (03:00) і далі —
дата збігається, дефекту не видно.

## Додатково

- Гіпотеза: `app/src/day-cap.js:6-8` — `dayKey` бере дату з `toISOString()` (UTC), а не з
  київського часу (`app/src/kyiv-time.js` уже має `kyivTime(instant).date`).
- Тести з коду `ai-runs/b1-from-code/day-cap.test.js` › `uses the UTC calendar day (not Kyiv
  local day)`, `the day boundary is midnight UTC (current behaviour)` і
  `ai-runs/b1-from-code/tariff.test.js` › `an after-midnight Kyiv ride is booked on the
  previous UTC day (current behaviour)` стверджують саму хибну поведінку (крок 5).
