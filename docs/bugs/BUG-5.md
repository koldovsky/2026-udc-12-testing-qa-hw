# BUG-5: денний ліміт рахує доби за UTC — поїздка о 00:30 за Києвом потрапляє у вчорашній ліміт

| Поле | Значення |
|---|---|
| **Правило специфікації** | T6 — «Поїздка належить до тієї доби, на яку припадає момент її **взяття** за київським часом» (`docs/spec/tariffs.md:101-102`); «Доба — календарна дата за київським часом, від 00:00 до 24:00» (`:34`) |
| **Середовище** | `main` = `4606c72` (до виправлення); Node v22.14.0; Windows 11 Pro, Git Bash |
| **Серйозність** | висока. Поїздки, взяті між 00:00 і 03:00 (влітку) або 02:00 (взимку) за Києвом, зараховуються до попередньої доби. Якщо вчорашній ліміт вичерпано, користувач їде безкоштовно. Якщо ні — нічні поїздки «з'їдають» вчорашній ліміт, і нова доба починається з повним лімітом |
| **Частота** | за умови: є журнал ліміту (`dayCap`) і взяття між 00:00 та 02:59 за Києвом (UTC+3) |
| **Знайдено** | `app/test/spec/t06-day-cap.test.js` › `T6: TC-35 ride on 17.09 00:30–01:00 is a new day: 2500 − 30 % = 1750` (`ai-runs/b2-run.txt`) |
| **Виправлення** | `d51cd03 fix(T6): book the daily cap on the Kyiv calendar date of the pickup` — `dayKey` бере дату з `kyivTime` замість `toISOString()` (`app/src/day-cap.js:8-10`) |

## Кроки відтворення

1. `git archive main app | tar -x -C ../ws12-main && cd ../ws12-main`
2. Один журнал `createDayCap()` і користувач `{ id: "r1", type: "standard" }`: три поїздки електровелосипедом
   16.09.2026 по 80 хв — 09:00, 13:00, 18:00 (Київ). Ліміт 16.09 вичерпано.
3. Тим самим журналом розрахувати поїздку цього користувача 17.09.2026 00:30 → 01:00 (Київ), класичний, `S01`.

## Очікуваний результат (за специфікацією)

Перші три — 12000, 12000, 6000 (`:105-106`). Поїздка взята **17.09** за Києвом → доба 17.09 (`:34`, `:101-102`),
ліміт 17.09 не використано. Уся поїздка в нічному інтервалі (T10, `:141`) → 2500 − 30 % → **1750**.

## Фактичний результат

`discounts: [night 750, day-cap 1750]`, `total: 0` — поїздку зараховано до 16.09 (`2026-09-16T21:30:00Z` — UTC-дата 16.09).

## Доказ

## Мінімальний вхід

`dayKey("2026-09-17T00:30:00+03:00")` → до виправлення `"2026-09-16"`, після — `"2026-09-17"`. Взяття о 03:00 за
Києвом і пізніше (UTC-дата вже та сама) — дефекту немає.

## Додатково

- Місце в коді: `app/src/day-cap.js:7` (до виправлення) — `new Date(pickupAt).toISOString().slice(0, 10)`, тоді як
  нічна знижка в `tariff.js` уже рахувала годину через `kyivTime`.
- Наявний тест `app/test/unit/day-cap.test.js` › `the day of a ride is the date of its pickup` перевіряв лише
  08:00Z, де UTC і Київ збігаються, — лишився зеленим, не змінювався.
- Тест AI «з коду» `ai-runs/b1-from-code/day-cap.test.js` › `dayKey gives the same key for instants on the same day`
  стверджував UTC-добу (`00:00:00Z` і `23:59:59Z` — один ключ) і почервонів (`ai-runs/b1-rerun.txt`), хоча агент у
  відповіді писав, що «навмисно не фіксує цю поведінку».
