# BUG-5: денний ліміт рахує добу за UTC, а не за київським часом

| Поле | Значення |
|---|---|
| **Правило специфікації** | T6 — «Поїздка належить до тієї доби, на яку припадає момент її **взяття** за київським часом» `docs/spec/tariffs.md:101-102`; «Доба — календарна дата за київським часом» `:34` |
| **Середовище** | `main` = `4606c72` (до виправлення, копія `../ws12-main`); після — коміт виправлення; Node v22.22.3; macOS (Darwin 25.6.0) |
| **Серйозність** | висока — поїздки, взяті 00:00–02:59 (літо) / 00:00–01:59 (зима) за Києвом, потрапляють у ліміт попередньої доби: користувач, що вичерпав ліміт напередодні, їде безкоштовно, а той, хто ще не їздив, може отримати урізання, якого не має бути |
| **Частота** | за умови взяття між 00:00 і 03:00 (літо) / 02:00 (зима) за Києвом і ненульових нарахувань на «сусідню» UTC-добу |
| **Знайдено** | `app/test/spec/t6-day-cap.test.js` › `T6, T10: TC-38 …` (`ai-runs/b2-run.txt`) |
| **Виправлення** | `a466d3f fix(T6): book rides on the Kyiv calendar day of pickup, not the UTC date` |

## Кроки відтворення

1. Журнал ліміту `createDayCap()`; користувачу `r1` нараховано 30 000 коп. 16.09 (`record("r1", "2026-09-16T09:00:00Z", 30000)` — 12:00 за Києвом).
2. Поїздка того ж користувача: взяття `2026-09-16T21:30:00Z` (= **17.09 00:30** Київ), повернення `21:50:00Z`, класичний, `S01`.
3. Викликати `quote()` з цим журналом.

## Очікуваний результат (за специфікацією)

Поїздка належить до доби 17.09, ліміт якої не використано → 25 грн − 30 % нічної (T10, `:141`) → **`total: 1750`**.

## Фактичний результат

Ліміт 16.09 «вичерпано» → рядок `day-cap` 1750, `total: 0`.

## Доказ

```bash
node -e 'Promise.all([import("./app/src/tariff.js"), import("./app/src/day-cap.js")]).then(([{ quote }, { createDayCap }]) => { const dayCap = createDayCap(); dayCap.record("r1", "2026-09-16T09:00:00Z", 30000); console.log(JSON.stringify(quote({ pickupAt: "2026-09-16T21:30:00Z", returnAt: "2026-09-16T21:50:00Z", bike: "classic", returnStation: "S01" }, { type: "standard", id: "r1" }, { dayCap }))); })'
```

До виправлення (`cd ../ws12-main && <та сама команда>`, код з `main`):

```text
{"minutes":20,"timeCharge":2500,"discounts":[{"code":"night","amount":750},{"code":"day-cap","amount":1750}],"fees":[],"total":0}
```

Після виправлення (у репо):

```text
{"minutes":20,"timeCharge":2500,"discounts":[{"code":"night","amount":750}],"fees":[],"total":1750}
```

## Мінімальний вхід

`dayKey("2026-09-16T21:30:00Z")` → до виправлення `2026-09-16`, має бути `2026-09-17`. Взяття `2026-09-17T07:00:00Z` (10:00 Київ) — дефект зникає.

## Додатково

Гіпотеза: `app/src/day-cap.js:7` — `toISOString().slice(0, 10)` дає UTC-дату. Виправлено через `kyivTime(pickupAt).date`. Тести з коду `ai-runs/b1-from-code/day-cap.test.js` › `uses the UTC date (current behaviour)` і `returns YYYY-MM-DD for ms and ISO input` (`23:59:59Z` → `2026-09-16`) зафіксували дефект.
