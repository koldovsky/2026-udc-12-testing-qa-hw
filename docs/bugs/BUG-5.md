# BUG-5: денний ліміт обліковується за UTC замість київської дати взяття

| Поле | Значення |
|---|---|
| **Правило специфікації** | T6: ліміт 300 грн на календарну добу за київським часом; поїздка належить даті взяття — `docs/spec/tariffs.md:98-107`. |
| **Середовище** | Початковий код `main` = `4606c72`; Node `v26.9.0`; Darwin. |
| **Серйозність** | Висока: той самий користувач може заплатити понад денні 300 грн або отримати безкоштовну поїздку нової київської доби через різницю дат UTC/Kyiv. |
| **Частота** | Завжди, коли взяття та попередні записи потрапляють у різні UTC-дати в межах однієї київської доби або навпаки. |
| **Знайдено** | `app/test/spec/tariffs.test.js` › `T6, T10: TC-36 daily ledger by rider and Kyiv pickup date`; також TC-37 у `ai-runs/b2-run.txt`. |
| **Виправлення** | `40bbb3e` — `fix(T6): key daily charges by Kyiv pickup date`. |

## Кроки відтворення

1. Із кореня репо створити копію початкового коду: `mkdir -p ../ws12-main`; `git archive main app | tar -x -C ../ws12-main`.
2. У корені `../ws12-main` виконати команду з розділу «Доказ». Для звіту копія була в `/private/tmp/ws12-main`.

## Очікуваний результат (за специфікацією)

Обидва взяття — 17.09 за Києвом: попередній запис `00:30+03:00`, нова поїздка `04:00–04:30+03:00`. У користувача U1 уже нараховано 30000 коп. за 17.09, тож погодинна плата за нову поїздку і підсумок — **0** (`docs/spec/tariffs.md:100-103`). T10 не змінює нульовий залишок ліміту.

## Фактичний результат до виправлення

`dayKey` відніс попередній запис до 16.09, а нове взяття — до 17.09; `total=1750` коп. Початковий `app/src/day-cap.js:6-8` брав `toISOString().slice(0, 10)`, тобто UTC-дату.

## Доказ

Команда з кореня копії `main`:

```bash
node --input-type=module -e 'import { quote } from "./app/src/tariff.js"; import { createDayCap, dayKey } from "./app/src/day-cap.js"; const d=createDayCap(); d.record("U1","2026-09-17T00:30:00+03:00",30000); const r=quote({pickupAt:"2026-09-17T04:00:00+03:00",returnAt:"2026-09-17T04:30:00+03:00",bike:"classic",returnStation:"S02"},{id:"U1",type:"standard"},{dayCap:d}); console.log(JSON.stringify({priorDay:dayKey("2026-09-17T00:30:00+03:00"),rideDay:dayKey("2026-09-17T04:00:00+03:00"),total:r.total}));'
```

```text
{"priorDay":"2026-09-16","rideDay":"2026-09-17","total":1750}
```

На виправленому коді: `{"priorDay":"2026-09-17","rideDay":"2026-09-17","total":0}`. TC-37 у `ai-runs/b2-run.txt` показує зворотний бік помилки: 0 замість 1750 у новій київській добі.

## Мінімальний вхід

Один запис U1 на 30000 коп. за взяття о 00:30 і одна нова 30-хвилинна поїздка о 04:00 тієї самої київської дати, обидва моменти з `+03:00`. Якщо обидва взяття лежать у тій самій UTC-добі, розбіжність зникає.

## Додатково

`app/test/unit/day-cap.test.js` не мав граничного прикладу; у коміті `40bbb3e` додано перевірки Kyiv/UTC без видалення наявної. Штатний `app/src/kyiv-time.js:14-21` уже вмів визначати дату в Europe/Kyiv.
