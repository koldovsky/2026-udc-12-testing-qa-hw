## 1. До: покриття рядків і мутаційний бал

| Показник | Значення | Звідки |
|---|---|---|
| Покриття рядків `src/` (`npm run coverage`, лише `app/test/unit/`) | 96,36 % (гілок 81,91 %) | `ai-runs/c-before.txt` |
| Мутаційний бал (`npm run mutate`, `app/test/unit/` + `app/test/spec/`) | 86,9 % | `ai-runs/c-before.txt` |
| Мутантів: вбито / вижило / таймаут | 73 / 11 / 0 (з 84) | `ai-runs/c-before.txt` |
| Тестів / викликів assert | 107 / 68 | `ai-runs/c-before.txt` |

Що означає різниця між першими двома рядками — своїми словами:
покриття лише каже, що рядок коду виконувався під час тестів; воно не перевіряє, чи тест
помітив би, що рядок працює неправильно. Мутаційний бал ставить саме це питання: для 11 з 84
змін у `tariff.js` і `day-cap.js` (наприклад, `>` → `>=` у межі денного ліміту, M023) усі
тести лишилися зеленими, хоча ці рядки «покриті». Тому 96 % покриття — і 13 % мутантів, яких
ніхто не помітив. Покриття рахується лише за unit-тестами, мутації — за unit і spec, тож
порівнювати числа напряму не можна, але напрям однаковий: рядків виконано більше, ніж
поведінки перевірено.
