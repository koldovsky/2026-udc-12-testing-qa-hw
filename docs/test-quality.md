# Якість тестів: покриття проти мутацій

> Task C. Скопіюйте у `docs/test-quality.md`. Усі числа — з файлів `ai-runs/c-before.txt`
> і `ai-runs/c-after.txt`, а не з пам'яті.
>
> Приклади курсивом — з **іншої** системи (онлайн-бібліотека громади).

## 1. До: покриття рядків і мутаційний бал

| Показник | Значення | Звідки |
|---|---|---|
| Покриття рядків `src/` (`npm run coverage`, лише `app/test/unit/`) | 96,34 % | `ai-runs/c-before.txt` |
| Мутаційний бал (`npm run mutate`, `app/test/unit/` + `app/test/spec/`) | 78,8 % | `ai-runs/c-before.txt` |
| Мутантів: вбито / вижило / таймаут | 67 / 18 / 0 | `ai-runs/c-before.txt` |
| Тестів / викликів assert | 39 / 60 | `ai-runs/c-before.txt` |

Що означає різниця між першими двома рядками — своїми словами, 2–3 речення:
Покриття показує, чи виконали тести рядки коду; воно саме по собі не означає, що
перевірили правильний результат. Мутаційний бал перевіряє, чи помітили тести штучні
зміни поведінки: зараз 18 таких змін лишилися непоміченими, попри високе покриття.

Що AI назвав запахом, а ви не погоджуєтеся, — і чому: суттєвих розбіжностей немає. AI
окремо назвав об'єднання GET `/` та GET `/api/health` у тесті eager test — це слушна
знахідка, яку я пропустив. AI не згадав слабку перевірку нічної знижки й помилкового JSON;
обидва пункти є в моєму списку, бо це конкретні твердження, які допускають неправильну
поведінку.
