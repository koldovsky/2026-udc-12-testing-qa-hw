## 1. Нестабільний тест локально

- **Який тест:** `app/test/integration/receipt.test.js` › `every receipt of a week of rides ends with the amount due` (назва на момент падінь; тепер — `T1 T3 T9: the receipt shows the amount due for rides at the 30 and 60 min block boundaries`)
- **Як часто падав:** 6 з 30 (`ai-runs/d-repeat-before.txt`: «Червоних прогонів: 6 з 30 (№ 8, 10, 19, 22, 23, 25)»; решта 70 тестів — зелені в усіх прогонах)
- **Повідомлення про помилку:**
  - `ebike, 30 min from 2026-09-21T14:24:00.000Z: got "До сплати .......................... 40,00 грн", expected 80,00 грн`
  - `classic, 60 min from 2026-09-21T14:44:00.000Z: got "До сплати .......................... 50,00 грн", expected 75,00 грн`
- **Причина:** дві речі разом. (1) **Хибний оракул у тесті:** очікувана сума рахувалася
  формулою `(Math.floor(minutes / 30) + 1) * PRICE` (`receipt.test.js:15` до виправлення), а
  T3 каже «за кожні розпочаті 30 хвилин» (`docs/spec/tariffs.md:62`, блок — `:29`), тобто
  `ceil(хв / 30)` блоків. Для будь-якої тривалості, що не ділиться на 30, обидві формули
  збігаються; для рівно 30 і 60 хв формула тесту дає на один блок більше (2 замість 1, 3
  замість 2). (2) **Невідтворювані дані:** фабрика (`app/test/helpers/factory.js:10–15` до
  виправлення) брала тривалість `Math.random()` з 5…89 хв без зерна, 10 поїздок на прогін.
  Прогін червоніє, лише коли хоч одна з 10 поїздок має рівно 30 або 60 хв: ймовірність
  `1 − (83/85)^10 ≈ 0,212` — збігається з 6/30 = 0,20. Код (`app/src/tariff.js` `blocks()` =
  `Math.ceil(minutes / 30)`) відповідає специфікації — дефекту коду немає, `app/src/` не
  змінювали. Інші приховані залежності перевірено й виключено: взяття 06:00Z + 0…600 хв =
  09:00–19:00 за Києвом (нічна знижка T10 не діє), станції лише S01–S08 (збору T7 немає),
  користувач `standard` (T4/T5 не діють), `quote` без `dayCap`, а максимум за поїздку
  120 грн < 300 грн (T6 не діє), тривалість ≥ 5 хв (T2 не діє).

## 2. Тріаж падінь CI

Кожен прогін з `ci/` — окремий розділ. Клас — один із чотирьох: **код** (дефект у коді
застосунку), **тест** (дефект у тесті), **середовище** (інфраструктура: ОС, мережа,
ресурси, зовнішні сервіси…), **нестабільний тест** (той самий код то проходить, то ні).
Класи можуть повторюватися, а якийсь — не трапитися жодного разу. Кожен клас — з
доказом, який можна перевірити.

**Як відтворював.** Кожну зміну — на свіжій копії `main` (`4606c72`), нова копія на кожен
прогін; Node v24.16.0, Windows 11 Pro 10.0.26300, Git Bash (у CI — Node v24.11.1, Ubuntu
24.04.3, рядок 108 і 6–7 кожного логу):

```bash
rm -rf /c/ws12-runs/ws12-d-repro && mkdir -p /c/ws12-runs/ws12-d-repro && git archive main app ci | tar -x -C /c/ws12-runs/ws12-d-repro
cd /c/ws12-runs/ws12-d-repro && git init -q && git apply ci/changes/run-NNNN.diff && npm --prefix app test; cd -
```

Рядки логу нижче — номери рядків у `ci/runs/run-NNNN.log` (`grep -n`). Перша помилка шукалася
двома командами: `grep -n "##\[error\]" ci/runs/run-NNNN.log` і
`grep -nE "Z (ℹ|✖) " ci/runs/run-NNNN.log`:
