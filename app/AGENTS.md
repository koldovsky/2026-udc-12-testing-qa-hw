# Правила для агентів у `app/`

## Тести

1. Бери очікувані результати з `docs/spec/tariffs.md` і вказуй ID правила T1–T10 у назві тесту. Якщо специфікації немає або вона не визначає результат, не виводь очікування з коду: познач неоднозначність.
2. Перевіряй конкретні очікувані значення для `minutes`, `timeCharge`, кожної знижки, кожного збору та `total`; перевірки на кшталт `>= 0`, `<` або лише `length` не доводять правильність тарифу.
3. Викликай справжню функцію, яку перевіряєш. Не підміняй `quote` або інший SUT mock-ом із заздалегідь заданим результатом.
4. Один незалежний сценарій — один тест. Розділяй різні маршрути, типи користувача й правила тарифікації, щоб збій точно показував, що не працює.
5. Для кожного правила з порогом перевір значення до, на і після межі; для календарних правил фіксуй часовий пояс та дату, до якої належить операція.
6. Знижки застосовуй лише до базової погодинної суми, якщо специфікація не каже інакше; окремо перевіряй коди й суми зборів, щоб знижка не змінювала їх.
7. Не змінюй наявні очікування, щоб зробити тест зеленим. Якщо очікування суперечить специфікації, покажи джерело й обґрунтуй окрему зміну тесту.
