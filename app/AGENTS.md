# AGENTS.md — правила для агента в `app/`

## Тести

1. **Очікувані значення в тестах — зі специфікації `docs/spec/tariffs.md`, з ID
   правила в назві тесту; ніколи — з поточної поведінки коду.** Якщо специфікації
   в теці немає — зупинись і скажи, що очікування перевірити нічим; не підставляй
   значення, які повертає код.
2. **Не змінюй перевірку чи очікуване значення, щоб тест пройшов, не пояснивши
   чому.** Червоний тест — це питання «хто неправий: код чи тест?», відповідь —
   лише за специфікацією.
3. **Оракул — точне число в копійках** через `assert.equal`/`assert.deepEqual`.
   Нерівності (`total <= cap`, `total < timeCharge`), перевірки лише типу,
   довжини масиву чи підрядка — заборонені: вони пропускають мутантів і помилки
   вдвічі.
4. **Очікуване значення — літерал, порахований руками зі специфікації.** Не
   обчислюй його формулами чи константами з `app/src/` (`RATES`,
   `Math.ceil(minutes/BLOCK)` тощо): оракул, який повторює код, не ловить нічого.
5. **Кожна межа зі специфікації — окремий рядок таблиці по обидва боки:**
   2:00/2:01 (T2), 30/31 хв (T3), 45/46 хв (T4), 1440/1441 хв (T8), 05:59/06:00
   (T10), остання копійка денного ліміту (T6). Однотипні кейси — таблицею даних
   у циклі, не копіями тесту.
6. **Тести детерміновані.** Без `Math.random`, `Date.now()` і читання поточного
   часу; без `sleep`/`setTimeout`, `retry`, `skip`, `todo`. Моменти часу — ISO
   8601 з явним зсувом (`+03:00`/`Z`); усе «добове» й «нічне» — за Europe/Kyiv,
   і вхід має розрізняти київську добу та UTC-добу.
7. **Кожен тест викликає продукт** (`quote`, `createDayCap`, `formatReceipt`,
   `createHandler`) **і впаде, якщо продукт зламати.** Тест, який перевіряє
   значення власного мока, — заборонений.
8. **Неоднозначність специфікації не вирішуй мовчки.** Кейс із відкритого
   питання (`docs/test-cases.md`, розділ «Питання до специфікації») або не
   автоматизується, або явно позначається в назві як поточна поведінка з номером
   питання.
